# 桌面端动效审计（apps/desktop 渲染层）

范围：`apps/desktop/src/renderer`（Electron 主窗口渲染层）及其复用的组件、样式、
主题文件。TUI/CLI 不在本次范围内。

审计方法：不按部件罗列，而是逐个检查"状态变化"——出现、消失、移动、变大小、换内容、
换图标、数值跳动、按下、悬停、加载、完成、出错——并回答两个问题：用户能否看懂这次变化？
变化是突然跳过去的，还是交代清楚了来去？

## 技术栈与既有约定

- React 19 + react-router（HashRouter）+ TypeScript，样式为原生 CSS，按 `@layer`
  分层（`reset, tokens, base, astryx-components, astryx-tokens, components, pages, utilities`）。
- UI 基座是 Astryx 设计系统（`@astryxdesign/core`），组件自带交互态与弹出层动画；
  Pico 的颜色、圆角、字体 token 由 `astryx-theme/pico.css`（生成文件）注入。
- 没有独立的 motion 库；改动前只有一条 token：`--motion: 160ms cubic-bezier(0.2,0,0,1)`，
  23 处引用，另有 8 个文件各自的 `transition`/`@keyframes`，曲线与时长互不一致
  （`120ms ease`、`140ms ease`、`160ms`、`180ms linear`、`s` 级 shimmer 混用）。
- 已有全局 `prefers-reduced-motion` 兜底（`styles.css` pages 层，把动画/过渡时长压到 0.01ms）。

## 统一 motion token（新增）

写入 `styles.css` 的 `tokens` 层，作为全项目唯一一套节奏：

| Token                  | 值                                  | 用途                                                                             |
| ---------------------- | ----------------------------------- | -------------------------------------------------------------------------------- |
| `--motion-fast`        | 120ms                               | 按下、悬停、勾选、高亮跟随等高频反馈                                             |
| `--motion-base`        | 180ms                               | 弹层/菜单出现、页面转场、内容替换                                                |
| `--motion-slow`        | 280ms                               | 大面板、抽屉等有明显位移的表面                                                   |
| `--motion-ease`        | `cubic-bezier(0.24, 1, 0.4, 1)`     | 主曲线，与 Astryx `--ease-standard` 完全一致，设计系统组件与自有表面共用一条曲线 |
| `--motion-ease-in-out` | `cubic-bezier(0.4, 0, 0.2, 1)`      | 双向循环（进度条等）                                                             |
| `--motion-spring`      | `cubic-bezier(0.34, 1.32, 0.64, 1)` | 仅强调：徽标、气泡计数等"出生"                                                   |

既有 23 处 `--motion` 引用已全部改写为显式 token（反馈用 fast，转场用 base），
保留单一来源，不再留别名。

`motion.css`（新增，`components` 层）只放命名关键帧与一条全局约定：
`motion-fade-in / rise-in / pop-up / pop-down / dialog-in / dialog-rise / toast-in /
slide-in-right / badge-in`，并让 Astryx 的 `<dialog>` 壳统一按 `--motion-base` 收口
（其默认取 `--duration-medium-max` = 400ms）。

### 1. 页面与面板转场

| ------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |

| 工作栏宽度拖拽                  | 无动画（指针驱动）     | 保持无动画；指针移动直接改宽度                                                                                                                         | 跟手优先                                                                           |

## 刻意不做（及理由）

- **工作栏/侧边栏折叠不补间宽度**：`width / flex-basis / grid-template-columns` 会逐帧
  触发布局，属于硬性禁止项。折叠仍是一次布局切换，靠内容淡入解释新状态。
- **不保留已删除元素的退出动画**：React 同步卸载节点，退出动画需要额外保留过期 DOM、
  推迟业务状态（归档/关闭面板/删除会话），会引入数据与视觉不一致。所有消失是即时的，
  到来有交代。
- **列表不做 stagger 延迟**：插入延迟会让用户等待，且新条目出现在列表中段时，
  延迟反而让人以为卡住。只用"逐条到达"的短动画。
- **纯文本数值不做数字滚动**：耗时每秒刷新、Token 数随流式增加，逐帧文字动画会产生
  持续噪声并增加字形重排；数值层面只做仪表（环）与进度（条）的连续化。
- **`<details>` 展开不做高度动画**：工具记录/思考块内容可能很大，`block-size: auto`
  过渡会持续触发重排；仅保留箭头旋转。
- **滚动条、文本输入、光标不加动效**：高频操作。

## 可打断性与性能

- 全部交互反馈使用 CSS transition（可持续、可反向），没有 `setTimeout` 动画链。
- 路由转场用 WAAPI，重复导航会先 `cancel()` 上一段，不会叠加。
- 拖拽/尺寸调整无动画，指针直接驱动。
- 进入/退出只动 `opacity` / `transform`（图片预览与抽屉的 `translate` 亦为合成属性），
  进度条改用 `scaleX` 消除宽度重排。
- `prefers-reduced-motion: reduce`：沿用全局 0.01ms 兜底（禁用所有补间与循环动画），
  并在 `motion.css` 额外把动画延迟归零，避免"淡入延迟"残留。
