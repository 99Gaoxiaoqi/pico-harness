# Pico 记忆整改：集成候选的行为与验证边界

核对日期：2026-10-16；文档基线为集成候选 `ee309a5c`，不是已发布版本的最终验收声明。本文替代旧[架构说明](14-workspace-memory.md)和[技术长文](../pico-memory-technical-guide.md)中的当前状态、Schema、恢复和召回说明；旧文保留为历史快照。

本轮保留用户级 SQLite、原始事件来源、事实与经验分层、版本检查和删除屏障。主要改变是：自动整理只做可证明的无损重复归档；新写入统一个人信息准入；续接问题可以找到原任务检索锚点；案例有独立身份与实际请求证据；持久待办和已登记工作区恢复已接线，但完整重启调度仍待最终验证。

## 事实、经验与原始事件各存什么

各工作区的 `pico.sqlite` 是原始消息、工具事实、Run 终态、checkpoint、会话设置和执行证据的权威来源。`$PICO_HOME/memory.sqlite` 保存长期记忆、经验与处理回执。同一 PICO_HOME 共用用户级开关；不同 PICO_HOME 隔离。global 内容只在符合准入的工作区使用，workspace 内容必须匹配其 workspace key。内部处理身份包含 workspace 和 session，不能只按同名 session 串联进度。

事实记忆使用 Item：正文、类型、陈述类型、时间类型/区间、观察时间、scope、版本、生命周期；keys 服务本地检索，sources 绑定原始 session/run/turn/event。常规事实提取只承认原始用户文本；助手文字可解释指代，工具结果和压缩摘要不自动变为用户事实。引文和模型可见范围都须核验，但引文逐字存在不保证语义解释绝对正确。

任务经验使用 task/observation/candidate/job、原生证据及引用/效果账本。case 是有来源的历史过程，method 是受审核、适用范围与当前条件约束的方法候选。经验引用身份与 Item 身份分开：candidateId、内容版本、记录修订不能伪装成 itemId。方法的审核、原生执行证据、引用是否实际送入请求、是否采用以及后续效果，是不同事实，不能相互替代。纯成功任务的自动经验反思仍默认关闭。

会话日志、长期内容与压缩视图的生命周期独立。删除长期内容不删除原始聊天；删除会话不会自动抹去已提交 Item，但来源可能变得不可读。删除代次阻止旧任务恢复已删除的记忆。用户可添加、更正、归档/恢复、删除、管理开关及查看处理状态；当前内容是否可用由实时状态决定。

## 写入触发与持久恢复

| 入口                       | 准入与完成含义                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 普通正常完成 Run           | 原终态必须携带合法自动提取准入；受用户开关、自动策略、工具可用性、信任与运行路径约束。失败、取消、recovered 终态不冒充正常完成准入         |
| `memory_extract({})`       | 登记显式提取请求，accepted 只表示已登记。仍需源 Run 正常完成或合法边界，不能提前当成已保存或额外授予工具权限                               |
| 合法 compaction checkpoint | 已提交覆盖范围与准入后可在 Run 尚未结束时安排提取；摘要本身不成为用户证据                                                                  |
| `memory_remember({})`      | 前台独占工具步骤并等待真实回执；请求不带模型任意提供的记忆正文。失败或未保存不能伪报成功，也不能仅因尝试过 remember 就压掉后续合法自动提取 |
| 明确保留助手回复           | 唯一定位授权用户事件和对应已完成助手原文，保存双来源参考笔记，标识未经独立核实；不把它升格为用户事实                                       |
| 手动添加/更正              | 本地校验与版本检查，操作同一权威库；不依赖后台模型重新猜用户意图                                                                           |

持久待办只保存源身份、冻结范围、触发和授权/删除屏障等调度 metadata，不复制整份聊天正文。应先有同一源事件库中合法、可恢复的准入事实，再投影中央 job；中央队列不能补造源权限。终态/checkpoint 的 admission 可选，缺失不能推定曾经允许。原事件已提交而 job 尚未投影的窗口，由 Runtime reconciliation 按原 admission 补投影。

启动恢复从既有登记列表出发，只进入受信且实际已有 `pico.sqlite` 的工作区，逐 session 核对已发布 catalog、cwd、未归档、持久 agent 设置、非 side 会话、已知且非 external boundary，并使用该 session 当前持久 modelRouteId。它不扫描任意目录、不借当前打开的 A 会话权限恢复 B，也不创建新前台 Run。模型使用独立 Provider/费用账本 lease；缺源工具上下文不伪造 Tool 定义。

每次 claim/模型阶段/提交仍须复核当前策略和代次；Host gate 重读登记、信任、catalog、设置与路由。关停使用主 atomicMemoryLifecycle：停止新工作，等待已开始工作及资源释放。待办状态用于区分等待、领取执行、有限延后、完成和终止；实际保存以事务回执和 cursor 为准。跨两个数据库不承诺“恰好执行一次”，靠稳定操作身份、租约与幂等提交防止重复写。

**完整恢复尚待最终验证。** 当前真实合成回归已证明源 terminal→job 窗口可恢复，也复现了旧进程入队、重启时尚未到期 job 缺少后续唤醒的问题。该修正及过期租约、有限重试/累计调用预算、删除/关闭屏障必须在最终组合验证；helper 不另造第二套 timer 或无限重试。此处不预告尚未定稿的 S 状态字段、次数或重试间隔。

## 程序可以归档哪些内容

自动整理只接受 duplicate：同 scope、kind、statementType、完整时间元组（含观察时间）和正文，且保留项覆盖被归档项的全部来源身份与检索键 metadata，才能无损归档。程序再次验证，模型提案本身不构成替代证明。

superseded、stale、low_value 不自动执行。updatedAt 是编辑时间，不是事实有效时间；同键、时间重叠、未知时间、多值和跨年度事实不能据此判定旧内容过时。用户明确更正仍走现有精确归因与归档路径，不被保守自动规则阻断。保留租约/版本/删除检查、6小时冷却、最多256个候选和整批30天撤销；不自动恢复历史归档。

## 新写入统一安全准入

事实提取的 proposal 与 canonicalize 对正文、keys、实际引文复用手动保存、助手笔记及经验使用的现有分类器。邮箱、电话、证件/支付类个人信息等 quarantine 结果按不写处理；secret 继续拒绝。不会把脱敏改写偷偷当作用户要求保存的原文。

显式 remember 还检查授权可见的原始证据，避免模型把敏感请求改写为安全摘要后冒充保存；自动混合批次可只过滤不安全候选、保留安全项。归整包括 NFKC、空白和与持久化相同的零宽字符处理。诊断保留受控原因码，不记录原始敏感正文。没有新增隐私授权豁免，也没有批量清洗历史记录；这些规则是当前可检测类别，不保证识别所有个人信息或秘密。

## 当前问题怎样变成召回参考

自动召回、主动事实搜索和预览共用 ContextBuilder。先收集路径、完整词和 CJK 双字信号，总量最多32；精确/前缀 key、正文和有限近期补位各有独立窗口，再按授权、生命周期、版本、资格和预算构造低信任原文引用。正文匹配不以“最近500条”作为全库资格边界。长事实优先保留完整条件/否定和原文区间；预算不足时跳过，不能把截断半句变成确定结论。

“继续”“按刚才方案”等有限续接语，可以从当前同一 session 的规范用户事件向前找有效任务锚点。候选须同工作区、可验证且没有取消/重置等断点；side/继承对话、引用/代码、缺源事件、显式新问题不借别的任务补锚点。查找有条数与长度预算，不能证明就用原问题。锚点只是查询提示，不是新指令、权限或提取来源。

词法扩展仅有一小组版本化中英别名，例如 build/构建、timeout/超时。原词和别名候选独立，原词优先；代码、路径、flags和身份赋值不扩成权限/方法条件。它不是通用同义改写、向量检索或额外模型检索。

方法和 case 在当前范围内先做资格核验与相关性排序，避免只看最新100条而漏掉较早相关项。扫描/异步条件核验有 deadline，受限结果必须标 limited，不能把 partial 无匹配说成完整全库零命中。自动方法引用最多1条，且须重验审核、内容版本、Host权限、范围和原生条件；case 仅提供历史过程。

| 读取/处理                       | 保留的预算边界                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 自动事实/方法参考               | 总3项、320 tokens，最多1条方法                                                                                                  |
| 主动事实搜索                    | 总10项、5120 tokens，单项480 tokens                                                                                             |
| case 搜索                       | 总3项、1500 tokens；预算包含实际引用块                                                                                          |
| 事实提取每处理范围              | proposal/localized/canonicalize及重试共用最多3次辅助调用；单次60秒。多个独立范围不是整个触发一共3次，重领任务不能重置同范围额度 |
| recall trace / request metadata | 8KiB；只裁诊断/来源 metadata，不能丢掉已选身份后假称完整                                                                        |

方法仍沿用 Item 的 memory trace；新 case 用 v2、recordType=case、caseSelected 和 caseReferences 保存 candidate 内容版本/记录修订及引用 hash，不伪造 MemoryItem。旧 v1 仍可读。queryRef 可保留 anchorEventId，queryPolicyVersion/hash 只作 metadata，查询和记忆正文不写入 trace。

请求事实对照 Provider 实际 prepared 正文的整块与逐条 hash；marker 或同名 toolCallId 不够。跨 Run 的 toolCallId 冲突无法唯一匹配时为 unrecorded，不选最近一条。执行页核对真实 candidate/Item 的当前修订、删除和源事件可读性；删除后案例及来源链接不可用，修订后不继续宣称旧来源当前可用。selected、prepared、响应已观测都不代表 adopted 或 verified。

## 缓存与单一本地词法索引

候选缓存只保存 ID/version 窗口，不保存最终正文 block 或授权结论。每 Builder 独立 LRU，最多64个 key、50,000个窗口身份引用、60秒 TTL；命中仍重读 Item、重验方法条件并重做排序/预算/trace。key 包含 workspace、设置版本、信号、模式、预算、方法资格和 Store revision；build 前后围栏遇并发写入最多重做一次，再冲突返回安全空结果/trace unavailable。缺 revision 能力时自动禁用缓存，不能假定 TTL 足以防止跨连接修改或删除。

索引是同一 SQLite 的 path/token/CJK posting，复用原词法与分数，不使用默认 FTS 分词或向量库。写/删/归档在原事务中清旧 posting、标记 dirty；查询以当前 scope/lifecycle JOIN 并同步 flush，最多命中项再做原评分复核。未知 query 形态、缺表/损坏/写入失败或复核不符，显式回退原扫描，不能吞成权威无命中。DDL/迁移与 Store revision/查询接线由 storage 单一所有者处理，正常打开不重建健康索引。

性能必须分“首次建索引”“预建后首次不同 query”和“重复 query”。同一台 macOS arm64/Node 26.7.0、合成临时库的正式旧路径基准：10k/50k正文检索 p95 约135/652ms。候选索引诊断 wrapper（尚非生产接线）得到：

| 合成 facts | 索引初建 | 40个首次不同query正文 p95 | 含重复query的200次正文 p95 | 索引库逻辑大小 |
| ---------: | -------: | ------------------------: | -------------------------: | -------------: |
|         1k |    112ms |                      36ms |                       34ms |        8.73MiB |
|        10k |    1.23s |                      91ms |                       29ms |       82.41MiB |
|        50k |   16.01s |                     347ms |                       31ms |      409.92MiB |

50k第一次读取若同时承担初建，合计约16.32秒，不能只报预建后约308ms的单次 query；初建事务可持写锁约16秒。相同50k旧库约231.36MiB，索引后约409.92MiB，明显增大。200次指标混有160次重复查询，不能冒充首次发现性能。以上是本机、固定语料的诊断结果，不是跨机器承诺；最终 Store/schema/revision 接线后的同 fixture 正式测量尚待完成。基准入口见 [scripts/eval/README.md](../../scripts/eval/README.md)，默认不调用模型或用户库。旧路径基准脚本提交为 `6859241a`，索引候选为 `b919e1ef`；本轮交付报告目录 `performance/` 保留 `baseline-6859241a.json`、`index-diagnostic-benchmark.json` 与 `index-integration.md`。诊断 wrapper 表格不是当前默认生产脚本已经测得的结果。
