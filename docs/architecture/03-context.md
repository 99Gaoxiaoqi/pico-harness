# 上下文：请求事实、有效历史与提示词装配

本文按 2026-09-23 的实现整理。完整机制与图示见[上下文技术详解](../pico-context-compaction-technical-guide.md)。

## 事实和投影

原始消息、工具输出、投影转换与 checkpoint 都保存在 Runtime 事件中。模型历史从这些事实重建；界面 transcript 保留原始执行过程。模型历史不会覆盖原始消息，也不再通过隐式读取预算改写内容。

请求发出前，Host 确定 Provider 路线、连接和窗口；Runtime 完成有效工具投影与 checkpoint 重放，并给出本次实际使用的压缩边界。系统提示、工具定义和新的输入随后组成 Provider 请求。`CostTracker` 冻结请求身份与组成，实际 usage 结算后同事务更新物理请求与最近成功主请求投影。

## 三种数值

| 数值               | 来源                                                 | 时间点         |
| ------------------ | ---------------------------------------------------- | -------------- |
| 实际输入与窗口占用 | Provider 输入用量／请求冻结窗口                      | 最近成功主请求 |
| 当前历史估算       | `chars_v1`：有效字符／4 向上取整，加适用工具图片估算 | 当前历史投影   |
| 累计用量           | 历次 canonical physical attempt 上报值汇总           | 整段会话       |

请求组成另保存语义 UTF-8 字节数；界面按字节比例展示，并以 `≈ceil(bytes/4)` 换算估计 Token。它与历史估算的字符算法不同，也不等于真实输入的可加总分摊。

## 执行策略

`prepareToolResultProjections` 在请求前提交必要的归档转换，`readModelHistory` 只读有效历史。旧结果保护最近两个用户 turn，活动结果按当前步骤与替代关系使用 2,048／256 Token 阈值。归档地址指向现有原始事实，不建立第二份正文库。

主动压缩根据 `I + O + min(2O, 8000)` 与用户声明窗口判断。一次 send 只有一次压缩尝试，成功模型步骤不刷新机会。无输出、未耗尽预算的真实溢出可以省略历史工具图片或摘要后重试一次；摘要失败保留历史。

`pre_turn` 保护当前任务；`mid_turn` 可折叠已完成步骤并重新附上任务；手动 `standalone` 可覆盖全部安全历史。工具配对、未闭合尾部、图片和实时引导约束边界。生成与校验完成后先提交 checkpoint，再应用模型投影。

## 所有权

- Runtime：执行循环、归档决策、摘要、历史投影和安全边界。
- Host：模型配置、请求计量装配、上下文查询与手动操作。
- Storage：canonical 物理请求和最新快照的事务持久化。
- App/TUI：消费同一个 v3 上下文契约，分别呈现事实与估算。

主代理、生产子代理和 Hook verifier 共用这条策略，各有自己的 Session、历史与 usage 锚。长期记忆拥有独立生命周期；本次上下文估算算法调整不改动长期记忆 tokenizer。
