# 文档 Agent 实施方案

目标：图片、文本、PDF、Word、Excel 上传后，Agent 按问题取证、读取和计算；大文档不会因为首次截断而永久丢失后文。

## 设计

- 保留会话附件存储、摘要校验、原文件导出和图片传输。替换文档全文注入：首次只提供目录信息、少量预览和稳定附件引用。
- 增加会话绑定的 `document` 工具：`inspect` 查看概况，`read` 按页/范围读取，`search` 搜索全文，`view` 查看 PDF 页图，`analyze` 计算 Excel 数据。输出必须说明来源位置、覆盖范围和续读参数。
- PDF 页面由随应用打包的 PDF.js/canvas 渲染；扫描页通过模型视觉读取。文本搜索不冒充扫描件 OCR；无视觉模型明确报告限制。
- Word 保留段落/表格位置；Excel 保留工作表、单元格、公式缓存状态。统计通过程序执行，报告筛选、空值、非数值、公式缓存等校验数据，不宣称重新计算公式。
- 文档解析在受限 Worker 中执行，保留上传、解压、超时和会话隔离检查。文档是数据，文件中的指令不构成新的操作授权。
- 本轮不扩展旧版 .doc/.xls、任意文档编辑、OCR 索引服务或通用 RAG。原附件不变，解析结果可重建；回退到上一应用包即可回退读取流程。

## 分工

1. 文档引擎：文本、Word、PDF 的概况、检索、续读和页图。
2. 表格引擎：工作表读取、检索、筛选分组统计及校验。
3. 宿主集成：会话工具、附件概况注入、权限/隔离和工具结果存储。
4. 主代理：公共契约、打包依赖、页图进入模型的链路、用户体验、集成和真实模型验收。

## 验证记录与边界

- 真实模型 `codex-oauth/gpt-5.6-luna-fast` 已通过六份附件验收：第 9001 行随机标记、文字 PDF、Word、两张 Excel 工作表与空单元格、程序求和、PNG 主色、纯图片 PDF 的随机六位数字；完成 7 次 document 调用。
- 真实模型测试发现运行中 Runtime 历史绕过媒体解析，已增加只读宿主媒体补全接口，覆盖运行中与重开后的请求；图片字节不写入会话事件。
- 文档源码中的普通链接和 Unicode 行分隔符不能伪造工具页图；越权引用、实际字节被篡改、取消及 20 秒超时均有回归验证。
- 单文件仍为 20 MiB；PDF 最多 1000 页，单张页图最多 4MP/4MiB；每次读取最多 16000 字符，显式续读。扫描件依赖视觉模型，不建立 OCR 文本索引。
- Word 当前读取正文段落与表格，不读取图片文字、页眉页脚、脚注尾注或批注。Excel 不重算公式，使用缓存并报告缺失/可能过期；单次范围最多 20 万单元格，搜索最多 50 万非空单元格，超限报错而非静默截断。
