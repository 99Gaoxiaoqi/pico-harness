# 上下文体系：对齐 Maka

本文对应 2026-09-23 的上下文对齐实现，固定参考 Maka `5846521372d2dd0d3d2d33dc7784dd046dc3f7c8`。详细原理及配图见[技术详解](../pico-context-compaction-technical-guide.md)。

## 历史与归档

模型历史依次应用原始 Runtime 事实、已提交工具投影、checkpoint 重放和 Provider 协议转换。原始聊天与工具正文继续保存；查询不会生成新的归档事件，也不会按隐式字节预算偷偷截短历史。

- 单次工具物理输出仍受 1 MiB 入口限制，超限时保存合成错误，要求从源头分段重取。
- 新结果先保存完整事实。下一模型请求前，`prepareToolResultProjections` 根据当前步骤与可见 reader 决定是否追加 `tool.result.projection.recorded`。
- 旧结果保护最近两个用户 turn，超过 2,048 个估算 Token 才归档；当前执行结果使用 2,048 阈值，被后续结果替代的内容使用 256 阈值。估算依据有效投影的序列化字符数除以 4，并向上取整。
- 投影事件持久化成功后才生效。重启、溢出恢复和查询继续使用已提交投影，不重新发送已归档全文；可见 reader 控制新增归档。
- 原文通过当前会话绑定的 `pico://archive/...` 地址回读，完整性由哈希和字节数校验。`archive_read` 提供 inspect、search、query、read；`read_file` 的归档地址入口使用 1 起始字符偏移。

## 触发、恢复与摘要

主动压缩只使用同路线最后成功请求的真实用量：

```text
I + O + min(2 × O, 8000) >= 用户明确声明的窗口
```

缺少声明或可信 usage 时不主动摘要。模型目录默认窗口与本地历史估算都不替代这个条件。

一次 send 对应一次 AgentEngine 执行，全部模型步骤共享一次压缩尝试标记。主动尝试开始即消耗标记；成功步骤不重置，失败也不在该 send 再走摘要恢复。新的用户输入或续接执行才重新初始化。

真实上下文溢出只有在该请求没有可观察输出、尚有步骤预算且未消耗恢复机会时才允许恢复：先省略符合条件的旧工具图片，否则摘要；重新应用工具投影后重试一次。无输出失败未完成模型步骤，因此最后一个尚未完成的允许步骤仍可重试。当前用户图片保留，预算耗尽的收尾请求不额外恢复。

| 阶段         | 安全前缀                                                 |
| ------------ | -------------------------------------------------------- |
| `pre_turn`   | 当前用户任务钉在未压缩尾部，只折叠此前完成历史           |
| `mid_turn`   | 可覆盖当前任务及完成步骤，任务原文重新附入；保留必要尾部 |
| `standalone` | 手动压缩不受主动阈值约束，可折叠全部安全完成历史         |

工具调用和结果不可拆开；未闭合工具尾部保持原文，之前的安全前缀仍可压缩。实时 steering 和当前用户图片约束切点。

摘要使用 Goal、Progress、Key Decisions、Next Steps、Critical Context 模板，最多 8,000 输出 Token，受路线输出上限约束。输出截断允许一次缩短重试，格式缺陷允许一次修复。相同会话和源内容的重复格式失败会锁存；更改来源后可再尝试。摘要器溢出只退到同路线已证明接受的前缀，不猜测任意比例裁剪。

顺序固定为“生成 → 质量校验 → checkpoint 持久化 → 应用”。来源条数、边界身份、内容摘要与摘要格式均须校验。滚动更新使用旧摘要和新增覆盖内容；写入失败不改变模型历史，不硬重置。

## 用量与展示

`session.context.get` v3 区分 `latestRequest` 与 `modelHistory`：

- 最近成功主请求：同次请求冻结路由、窗口、请求组成及使用的压缩边界，结算实际 usage。canonical physical attempt 与最新快照投影同事务保存；失败、摘要和 Hook 不覆盖主快照。
- 追踪主指标：实际 `I / 当次窗口`；缓存属于输入子集。组成使用语义 UTF-8 字节数，展示 `≈ceil(bytes/4)`，不伪装为精确 Token 分摊。
- 当前历史：消息数和 checkpoint 是事实，Token 使用 `chars_v1` 估算；不包含完整系统、工具及协议开销。
- 输入框：实时使用 `I`，同模型／连接的最新锚点回退使用 `I+O`；窗口依次取用户声明、请求冻结值、模型元数据。切换目标清理旧值，迟到响应不得覆盖新目标。
- 累计用量独立显示。手动压缩后，当前历史可以变化而最近请求快照仍保持原值。

主会话、配置型／Graph 子会话和 Hook verifier 均通过独立 Session 的 AgentEngine 使用相同上下文策略。旧 `runSub`、独立字符裁剪、兼容导出已移除。Hook 保留只读工具、取消与独立计量边界，且不挂载 Hook 服务以防递归。

## 验证方式

确定性集成覆盖触发矩阵、一次 send 标记、可观察输出、步骤预算、阶段边界、摘要质量、持久化失败、归档重放、快照事务和界面切换。三种 Provider 协议校验摘要输出预算映射。

```sh
npm run build:packages
node scripts/run-integration-tests.mjs maka-compaction compaction-rolling-digest compaction-review-fixes compaction-output-budget tool-result-runtime-projection hook-verifier-compaction
```

真实模型验证还需执行 `tests/e2e/` 的自动触发、摘要质量、工具归档和 Hook 场景。受控测试能覆盖指定分支，不代表生产负载中的自然触发概率。最终通过数量和实机结果以本轮验收记录为准，不复用旧版本测试结论。
