# 自然验收与自动晋升实施记录

已实施用户确认的自然任务验收方案：真实失败 → 原生修复 → 复测 T1 前冻结主张/条件/票据 → 自然执行产生 T2 → 空闲后台核验与原子保存 → 新 Session 按当前入口范围召回。主流程不等待学习模型，后台不主动重跑命令；手动 `memory_learn` v1 保留。

## 当前边界

- `test-target-pass.v1`：显式 Node `node:test` 文件列表、失败节点、完整固定 reporter 报告、原生退出码和实际 Node 运行器身份一致（路径、版本、可执行文件元数据摘要）。改动测试入口或通过不同测试节点不能晋升。
- `command-conditions.v1`：静态本地入口、真实 cwd、普通小型配置文件摘要，或单个静态 `npm install` 的本地包清单、版本及普通入口。带 exports 的包、复杂包装命令和其他测试框架暂不自动验收。首版只接入 POSIX shell；Windows PowerShell 保持原命令，不做自动插桩。
- 配置模板保留实际原生提交内容；目录显示与命令入口相对其正确作用域表达，不改写配置值。模板不能完整装入预算时保留候选，不截断后宣称验收。
- 模型根因仅保存为隔离假设。正式经验是经过验收的操作方案，不宣称因果成立或未来必定成功。
- 召回前复核工作区和入口源码。准备文件/依赖缺失仍可召回，供 Agent 先准备再验收；最多一项。Node 运行器按实际命令/PATH 解析其物理路径，并复核可执行文件元数据摘要；Electron Host 与外部 Node 可共存。缺失身份或运行器变化时保守排除，不额外运行检查命令。

## 生产约束

每个 PICO_HOME 使用独立 SQLite 连接和全局持久租约，前台空闲 10 秒后整理；模型超时 60 秒、租约 90 秒。每个原始失败最多两次反思，每工作区每小时最多四次，取消也计数。设置、删除代次、管理代次和墓碑在预算及保存事务中复核；关闭自动提取时不会创建新模型请求。

普通新输入只抢占旧反思，保留已冻结候选和自然验收票。旧反思不能覆盖已保存或已修订的候选，也不能让新输入的待验收候选失效。明确经验纠正、手动管理、删除和丢弃阻断旧晋升。前台可选证据登记每次最多 100ms、观测最多 8 路径/2MiB，失败不改变原生工具结果。

v9/v10 增量升级到 v11，保留既有 Item 和手动 v1 候选。重启恢复过期租约和已持久化的验收回执；缺失历史 before/after 的票据不会用当前文件状态补证。候选保留 30 天、终态任务 7 天；丢弃或删除清除模板/假设并保留无正文墓碑。

正式 Item 绑定持久 `execution-validated` 来源与 taskAcceptance。元数据缺失或内容摘要失配时排除召回，不回落用户事实；明确人工更正转为手动内容。桌面 `memory.learning.list/inspect/discard` 与 `memory.learning.changed` 提供持久状态：会话按 Run 折叠，记忆页可查看原生来源、丢弃候选和查看正式方案。
