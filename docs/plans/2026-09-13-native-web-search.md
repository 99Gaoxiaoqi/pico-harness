# Pico 模型原生联网改造

## 目的与依据

采用 Maka 的分层方式：先解析模型与协议，再判断该连接的搜索能力，最后按用户选择给这次运行装配搜索工具。联网开关只允许模型按需搜索，不保证每次回答都搜索。

本地 Maka 参考为 `packages/core/src/model-web-search.ts`、`packages/runtime/src/native-web-search-tool.ts` 和 `packages/runtime/src/model-adapter.ts`。不能仅按模型名称或 Responses 协议宣称已经支持联网：DeepSeek 官方 Responses 的现有 SDK 会过滤原生工具，此前真实请求也只返回普通 message，没有搜索事件，因此这条连接明确标为不可用。

## 配置与流程

1. 在现有用户配置 `defaults.webSearch` 保存 `{ enabled, source }`，来源为 `model`（当前模型）或 `external`（现有 SEARCH_API_BASE / SEARCH_API_KEY 服务）。未配置时关闭；旧配置和模型密钥原样保留。设置走现有 revision 并发校验，下一次运行读取。
2. 对话选中的 modelRouteId 决定连接和模型。逐模型 modelProtocols 显式设置优先；缺省时只为官方 DeepSeek V4 Flash/Pro 补 Responses 默认值。其他连接沿用明确协议，不试错切换。
3. 能力判断同时检查协议、端点、模型和显式 webSearch 能力覆盖；未知兼容端点默认不可用。实现不支持的 SDK 路径不能被能力覆盖强行启用。
4. 开关关闭则移除 web_search；external 仅使用现有外部服务；model 仅注入匹配 SDK 的 provider tool。不可用时提供原因，不更换搜索来源。
5. 主对话、配置型子代理与 Graph/Swarm 操作员在运行时使用相同装配规则。子代理工具白名单和网络边界是权限上限；原生搜索不绕过网络授权。后台限定域名无法约束供应商搜索，只有网络 allow 才允许原生搜索。辅助模型调用与 tool_choice:none 不携带原生搜索。
6. Provider 使用 SDK 原生搜索工具，原生 call/result 不进入 Pico 本地工具执行。保存真实搜索事件和来源供 UI 展示，并保留供应商数据供下一轮重放。只返回文字或链接不能当作搜索执行成功。

## 分工

- 配置代理：配置持久化、协议默认与能力解析、桌面只读能力 DTO、对应集成测试。
- Provider 代理：SDK 请求、结果与来源、重放、模拟接口集成和真实接口探测脚本。
- 桌面代理：联网设置、能力不可用原因、搜索结果展示及 UI 测试。
- 主代理：运行时权限与工具装配、子任务一致性、合并与最终验证。各自独立 worktree。

## 验收

- 配置开启/关闭/来源往返且不丢其他设置；显式协议优先、缺省兼容规则只命中已知连接。
- 原生请求包含正确搜索工具且保留普通工具；关闭、权限不足和子代理工具上限不泄漏搜索能力。
- 搜索 call/result/source 保存与重放完整，模型原生调用不会在本地重复执行。
- 桌面展示真实状态；普通回答不显示“已联网”。
- 运行相关集成测试、类型检查和适当的真实接口探测；真实端点不支持搜索如实记录为不可用，不伪造成功。

## 回退

关闭联网开关即可停止新增搜索工具。来源可明确选择 external 复用旧服务；不自动切换。Git 变更在独立集成分支验收后才更新主分支，保留原工作区已有 UI 修改。
