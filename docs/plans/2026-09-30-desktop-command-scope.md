## 结论

Pico 应借鉴 Maka 的“共享命令定义、按界面显式选择”方式。共享 TUI 的语义和执行能力，不意味着桌面输入框需要暴露全部 42 条命令。

已将 42 条命令划分为：

| 分类       | 数量 | 桌面处理                                                         |
| ---------- | ---: | ---------------------------------------------------------------- |
| A 常用命令 |   12 | 输入 `/` 时默认展示；按会话状态禁用并说明原因                    |
| B 高级命令 |   15 | 不占用默认列表；输入匹配前缀或进入“全部命令”后可发现、执行       |
| C 界面承接 |   11 | 不保留同名命令的业务执行器；误输入时提供准确的界面入口和范围说明 |
| D 不迁移   |    4 | 桌面拒绝执行并解释原因；TUI 保持现状                             |

因此桌面实际支持 **27 条执行命令**，默认展示 **12 条**，**15 条不迁移为桌面执行命令**。C 类仅提供导航或说明，不继续偷偷调用原 TUI 管理命令。别名跟随主命令策略，不另外计数。

这是根据当前代码和交互成本作出的首版范围，尚无用户使用频率数据支撑“常用”排序。不要将这些数量视为必须长期维持的指标。

## 桌面交互规则

- 空 `/` 默认列出 A 类 12 条；B 类在匹配前缀或“全部命令”中出现，并标记高级。C/D 不进入可执行候选。
- `/help` 默认解释 A/B；识别到 C/D 名称或别名时，显示迁移说明、界面按钮或 TUI 指引。输入 `/provider delete ...` 不应仅因已知命令名就执行删除，也不应作为普通任务发给模型。
- 未知命令保留草稿并显示提示；普通文本中的斜杠不触发命令。IME、方向键、Tab、Enter、Esc 保持已实现行为。
- `/goal`、`/resume`、`/model`、`/skill`、`/agent` 无参数时打开相应已有选择器或表单；查询命令不为了执行而创建临时项目/空 Session。尚无会话时，只有明确支持的动作可用，其余解释前置条件。
- 主聊天与侧边聊天使用同一范围策略，但作用域不同：会话操作绑定输入所在会话；新建、恢复、分叉等导航明确打开主聊天目标，不能静默把侧边子会话改成另一个会话。涉及会话切换的异步结果不得污染新目标。
- 保留运行状态、模态交互、权限和审批约束。键盘执行与按钮必须经过同一领域动作；共享 TUI 解析器仅负责理解参数，不能绕过桌面已有的确认流程。

## 实施顺序

### 第一步：收敛范围与执行边界

建立上述策略表；同时限制菜单、帮助、补全和实际执行。移除 C/D 在桌面的原 TUI 执行路径及多余主进程许可，保留明确的迁移提示。已有用户样式和并行修改不纳入变更。

完成标准：桌面默认候选为 A 类，实际执行仅 A/B；手工输入 C/D 或别名也不会触发管理 RPC、退出、隐藏历史或模型请求；TUI 仍保留全部能力。

### 第二步：接回已有桌面交互

模型、Goal、模式、权限、会话动作调用现有控件/领域动作；保留检查点界面补足真实缺口。C 类按钮指向当前已有页面或选择器，准确携带 workspace/session；不为高级 Cron、插件管理等建立新页面。
