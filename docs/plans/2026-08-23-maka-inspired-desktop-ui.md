# Pico Desktop UI 重写

状态：实现与本地验收完成，发布未执行。右侧多标签 Session Workbar 作为后续独立交付，不在本次 UI 重写中伪造尚无底层 authority 的功能。

## 目标

把 Desktop 从“管理后台 + 聊天气泡”重写为面向本地 Agent 的任务工作台。交互参考 Maka，但保留 Pico 自己的产品语言：高信息密度、低装饰、执行过程可检查。

## 当前问题

- 开始页由指标卡和面板主导，用户进入任务的路径不够直接。
- 会话内容仍以离散卡片为主，工具、子代理、计划和状态之间缺少连续的执行脉络。
- 右侧只呈现 Environment，未形成稳定的任务工作台心智。
- 通用页面的标题、容器和设置布局存在，但视觉层级不够统一。

## 目标信息架构

1. 左侧任务导航：新任务、定时任务、按项目分组的历史任务和设置；Skills/MCP 等工具能力收拢到设置。
2. 中间任务文档：用户问题、回答与执行记录形成一条连续的执行脊柱；输入框始终在底部。
3. 右侧工作台：按需查看任务概览、文件变更和运行上下文；详情 Inspector 临时覆盖这一位置。
4. 设置与资源页面：使用统一的内容标题、分区行和状态表达，不改变已有数据作用域。

## 范围

### 本次包含

- 重做设计 tokens、应用壳、侧栏、标题栏和页面容器。
- 重做开始页，使“开始任务”和“继续任务”成为唯一主线。
- 重做会话标题、文档式 transcript、执行记录、悬浮 composer 和右侧工作台。
- 统一设置、记忆、能力、Provider、用量等既有页面的基础视觉语言。
- 在真实 Electron 窗口中验证主要导航、新任务、会话和侧栏/工作台折叠。

### 本次不包含

- 除新建 Session 首次发送所需的 `initialSettings` 外，不扩展 Runtime 领域 API；开发态 daemon 启动与旧工作区降级属于独立支持性修复。
- 不改 `{workspacePath, sessionId}` 复合身份、路由作用域和会话恢复协议。
- 不改 `steer / queue / replace`、审批、提问、Plan、CAS/revision/fingerprint 语义。
- 不新增虚假的终端、浏览器、文件或用量数据。
- 不改变 session 与长期记忆的生命周期关系。

## 关键设计决定

- 使用冷灰导航、白色任务画布和克制的靛蓝强调色；无渐变装饰，阴影只用于输入框和临时浮层。
- 用户消息保留轻量引用面，Assistant 输出保持文档正文；工具、计划和子代理改为紧凑的执行记录，而不是大卡片堆叠。
- 右侧工作台只暴露 Pico 已有真实数据：任务环境、变更、模型/权限/协作模式和 Runtime 状态。
- 保留所有可访问性与桌面行为：键盘导航、焦点、`drag/no-drag`、reduced motion 和窄窗口降级。

## 验收

- Runtime 连接后能从左侧创建任务、切换工作区会话和进入资源页面。
- 新任务页直接聚焦任务输入；发送只执行一次，并导航到正确工作区会话。
- durable transcript、live timeline、审批/提问、目标和探索无重复合并。
- 运行中的暂停、恢复、停止以及 steer/queue/replace 仍可用。
- 右侧工作台可折叠，Inspector 可正常替换并关闭。
- 980px 与最小窗口宽度下无关键内容遮挡；键盘焦点可见。
- Desktop typecheck 与相关集成测试通过。

## 回退

本次没有数据迁移。若验收失败，可以回退 Renderer 重写及独立的首次发送设置契约；无需恢复 Session、EventLog 或长期 Memory 数据。
