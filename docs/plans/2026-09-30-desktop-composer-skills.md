# 桌面统一输入与 Skills 对齐计划

日期：2026-09-30。状态：四阶段代码已集成，18 项针对性集成/UI 测试、桌面类型检查及打包通过，重新安装与 Computer Use 对照验收已完成；双技能真实模型测试因 Provider 402 余额不足待补测。

## 目标与依据

让 Pico 的命令、技能和 Agent 围绕同一份任务草稿工作：用户能在输入框发现能力、选择标签、继续编辑，并在切换会话、重启和发送失败后恢复完整草稿。借鉴 Maka 的统一输入体验，同时沿用 Pico 的结构化执行与授权边界。

本计划承接已经实施的[桌面命令范围方案](2026-09-30-desktop-command-scope.md)，不重新定义 42 条命令的 A/B/C/D 取舍。主要依据是[本轮实机对比与源码记录](../../output/desktop-skill-comparison-20260930/report.md)：Pico 已复现技能标签随会话切换丢失；加号与 slash 的无项目可用条件不同；Skills 发现缺少 `.agents/skills`；独立技能选择器缺少方向键选择；多技能尚无提交契约。

本轮交付包括主聊天、侧边聊天、新任务的统一候选与技能草稿，以及端到端多技能输入。Agent 保持一次输入一个委派目标，不将多个 Agent 当作多个 Skill。文件附件、`@` 文件/会话引用单列后续里程碑，见文末。

## 最终交互约定

- 输入 `/`：展示常用命令及 Skills 分组；高级命令仍按既定策略搜索发现。Agent 候选通过 `/agent` 或加号的“子代理”筛选进入，复用同一候选组件。
- 输入 `/技能名` 或中文说明：查询技能名称、描述；命令名称和别名仍优先精确识别。命令与同名技能用分组及类型明确区分，选择后由类型分派，不能把技能当命令执行。
- 正文中输入 `/`：只建议技能，不执行会话命令；URL、路径和一般正文中的斜杠不误触发。采用光标位置与编辑器 trigger 判断，不扫描整段文字猜测当前输入。
- 命令选择先补全；明确的完整命令按已有 Enter 执行规则处理。技能、Agent 选择只插入标签，不发送任务；用户继续编辑后主动发送。
- 技能标签位于正文中，可添加多个、按当前顺序保存、删除或去重。Agent 标签体现独立委派语义；本轮 Skill 与 Agent 不混合提交，切换类型时保留文字并给出明确替换提示。
- 加号的“选择技能”和输入 `/` 打开同一个技能候选源；“选择子代理”打开同组件的 Agent 分组。无项目时允许选用户级能力，首次发送仍走已有工作区创建及信任流程；项目未可信时不启用项目能力。
- 候选菜单悬浮在输入框附近，不挤高输入框；小窗口自动适配可用空间。分组、禁用原因和中文文案清楚，不显示 daemon 等实现术语。
- 共用 ↑↓、Tab、Enter、Esc、鼠标选择及 IME 保护。Tab/Enter 选技能时不得意外发送；屏幕阅读器能读取当前候选、类型、选中状态及可移除标签。

## 实施阶段

### 第一阶段：完整草稿与入口一致性

先解决已经复现的行为缺陷，使这一阶段可独立交付。

改动范围：现有 `usePersistentDraft`、主聊天 `ConversationPage`、侧边聊天 controller，以及加号/slash 的技能入口。

- 扩展现有按 workspace/session 保存的草稿，文本及结构化引用共同读写。引用保存类型、规范身份和标签信息，不保存技能正文；后续正文标签使用同一份数据，不再维持第二套 activation 状态。
- 兼容已有纯文本草稿；通过新格式标记区分，保留旧数据。截断和大小限制不能切出半个标签；存储不可用时继续保留内存草稿。
- 恢复时在当前有效 Catalog 中校验引用。资源消失或同名来源改变时明确标记并要求重新选择，保留文字，不能悄悄换技能。
- 发送成功仅清理来源草稿；失败保留文字和选择。异步响应不能清掉用户切换后正在编辑的另一会话草稿。
- 加号与 slash 共用可用条件及范围；主、侧聊天保持独立草稿键。第一阶段可继续显示现有单标签，但保存方式已为正文引用提供统一来源。

验收：选 github → 写文字 → 切换两个会话 → 返回 → 重启，文字与标签均恢复；发送失败同样保留；迟到成功不清理另一会话草稿；无项目时两入口一致。用真实 React 页面集成测试覆盖主路径与关键失败路径，并保留既有草稿回归。

### 第二阶段：共享 `.agents/skills` 发现

改动范围：Pico Host 的 SkillLoader/资源目录投影，以及必要的资源来源类型；桌面与 TUI 共同使用宿主目录。

- 添加项目 `.agents/skills`、用户 `~/.agents/skills`，复用 SKILL.md 解析、目录冲突和来源投影规则。
- 推荐优先级如下；既有来源之间的相对顺序保持，插件继续采用原有授权与优先级，不改成用户目录。

| 来源                    | 建议优先级 |
| ----------------------- | ---------: |
| 项目 `.pico/skills`     |         50 |
| 项目 `.agents/skills`   |         45 |
| 项目 `.claude/skills`   |         40 |
| 用户 `PICO_HOME/skills` |         30 |
| 用户 `~/.agents/skills` |         25 |
| 用户 `~/.claude/skills` |         20 |

- `.agents` 是独立兼容来源，不绑定 Claude 兼容开关。发现不等于执行授权；项目信任、Hooks 审核和已授权插件边界继续生效。
- 同名冲突按当前规范名称解析，沿用当前解析行为；现有畸形 frontmatter 的错误跳过/回退机制本轮未增加 tombstone，不能承诺错误的高优先级声明阻止降级。展示真实来源与覆盖关系，首次发送和已有会话解析必须得到同一个有效资源。
- 本轮不新增 `.codex/skills` 或自动复制用户目录。

验收：临时 home/project 中的 `.agents` 技能同时进入桌面及 TUI 的有效目录；同名覆盖、禁用 Claude 兼容和不可信项目行为符合约定；实机能找到本机 aihot、archify。扩展现有宿主 Catalog 集成测试，不通过 renderer 扫磁盘补名单。

### 第三阶段：统一候选与正文标签

依赖第一阶段的草稿表示和第二阶段的 Catalog。改动范围：共享 Composer、候选及上下文选择组件、命令接入 hook、主/侧聊天适配。

- 优先复用现有 Astryx 编辑器 trigger/token 能力，合并当前独立命令菜单与技能选择器；不直接引入 Maka 整套 Composer。
- 候选项携带命令/Skill/Agent 类型，统一搜索、排序、光标定位及分组；名称精确匹配优于描述匹配，支持大小写无关和多词查询。
- 技能生成正文标签，序列化进入第一阶段草稿；编辑、删除、复制粘贴、切换恢复走同一条路径。已选技能在候选中去重。
- 保持 `/skill <name> [args]`、`/agent <name> <task>` 和既有别名有效，结构化引用在发送前解析，不拼成用户可伪造的提示词来绕过宿主验证。
- 空 `/` 中的默认命令范围、高级命令搜索以及 C/D 导航/拒绝策略继续由主进程验证。正文技能建议不能误执行 `/clear`、`/exit` 或其他会话命令。
- Agent 使用同一候选和草稿体系，但保持独立标签类型及既有委派 payload。单技能可在此阶段真实发送；多技能发送在第四阶段完成后才开放。

验收：新任务、主聊天及侧边聊天完成“搜索 → 键盘选择 → 编辑标签和文字 → 切换恢复”；`/aihot`、中文说明、多词查询正确；IME 确认选词不插入技能或发送；路径和 URL 不误触发；同名命令与技能无歧义。浏览器/Electron 集成测试共用真实组件，实际 Runtime reload 不得被空函数掩盖。

### 第四阶段：多技能提交与最终安装验收

依赖第三阶段。公共输入契约由主代理单一负责，改动范围按完整调用链确认：protocol、renderer RuntimeActions、主进程/宿主校验、输入解析、排队与恢复、执行约束、会话投影和 TUI 兼容。

- 在既有输入上增加向后兼容的结构化多技能引用；保留旧 `kind: skill`、Agent 和纯文本输入。正文显示名称，传输用规范身份，不将 Maka 的 `/skill:<id>` 语法直接假定为 Pico 已支持。
- 新能力通过现有 Runtime capability 握手确认；连接旧 daemon 时禁用多技能发送并提示更新，保留草稿，不把未支持字段静默降级成普通文本。最终安装验收确认实际连接的 daemon 支持新契约。
- 宿主在创建会话或入队前校验全部引用及当前有效来源。任一技能无效时整体拒绝，保留草稿；不半执行、不静默忽略。
- 同一条任务输入按标签顺序加载多个技能，规范身份去重；只创建一次任务。排队、失败重试、重启恢复保留完整引用并复用已有幂等机制。
- 工具限制按共同允许范围组合，未声明限制不扩大其他技能限制；模型声明相同则使用该模型，冲突时明确拒绝并提示调整选择。权限冲突不能通过简单并集绕过。
- 多个技能的 Hooks 复用现有信任检查，按引用顺序、按真实来源绑定执行；进入执行前完成所有校验。扩展现有单个 skillActivation 承载的必要路径，避免只拼接正文而丢失 Hooks、模型或工具限制。
- 用户消息和执行投影能追溯实际采用的技能身份；编辑重发、队列恢复及侧边聊天不得丢失引用。无参数技能按已有规则保留兼容，选择动作本身不启动模型。

验收：一条任务带两个不同技能，宿主解析均正确、只启动一次；去重、无效引用、模型冲突及失败重试结果明确；队列和恢复保持身份。用确定性集成测试覆盖协议与状态链路，并在 `tests/e2e/` 使用两个受控技能做一条真实模型验收；模型环境失败时记录具体失败，不写成已通过。

最终在完成状态运行受影响类型检查和构建，重新打包、安装 App，用 Computer Use 对比 Maka：技能搜索、正文多标签、删除、切换/重启恢复、首次发送、失败反馈、主/侧聊天，以及上一轮命令关键回归。记录源码、安装产物和实机证据，达到清单后停止。

## 协作边界

- 本次只制定计划；现有未提交命令实现及用户修改保留。
- 开发时第一阶段 UI/草稿与第二阶段宿主 Catalog 可在冻结来源类型后独立推进；存在清晰收益时并行。第三、四阶段按依赖集成，不并行修改同一 Composer、Schema 或锁文件。
- 主代理拥有公共契约、数据格式与集成验证。并行代码任务按项目要求使用独立 worktree 和唯一任务分支；开始前先确认当前已实现命令基线及未提交文件归属，不自动 stash/reset 或混入用户修改。
- 验证只扩展受影响集成链路。持久化和协议阶段追加必要类型/构建检查；最后集中进行一次打包和实际安装验收。

## 后续独立里程碑：文件与会话引用

目标是与 Maka 的上下文入口继续对齐，先核实 Pico 已有文件读取/附件和会话快照能力，再实施 `@` 文件与会话候选、结构化引用、权限检查和草稿恢复。

这一里程碑不混入上述四阶段，因为文件引用、文件上传和会话引用语义不同。开始时需要确认传输与权限调用链，分别定义目标项目、快照时点、资源消失时的错误以及发送前可见内容。验收必须证明引用到的真实内容与目标身份一致，不能仅做标签外观；用户文件不随调查自动上传。

## 风险与回退

主要风险是新草稿格式丢失旧文字、多技能放宽执行约束、排队恢复丢身份，以及标签身份与宿主实际解析来源不一致。分别通过旧格式兼容、宿主先校验、全链路持久化及来源校验控制。

各阶段保持可独立交付；升级草稿时保留旧文本恢复通道。回退只针对本任务变更和安装包，先导出新格式草稿保留用户文字及标签信息；不清空本地存储、不删除会话，不对整个工作区执行 reset。
