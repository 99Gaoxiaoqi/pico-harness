# 经验闭环修复验收（2026-10-13）

本轮集成用户明确授权的全部既有未提交改动，包括经验闭环、附件与移动端。实现于独立集成分支；原工作区内容先保存快照，未使用 stash 或 reset。

## 修复结果

- 每个物理请求独立冻结引用诊断，取得可信整数 HTTP 2xx 才确认携带。发送前取消、网络结果未知和错误请求不能冒记引用，兼容重试不能借用其他请求的片段。
- 历史携带依据原生物理请求、Run、工作区绑定、canonical ModelStarted 和片段哈希核对。缺少证据仅纠正读投影，不覆盖独立效果和用户决定；未经核实不能产生新的采用或自动停用。
- 查询、详情和用户反馈采用一致的携带投影；旧接口完整排除无法表达的新增未确认记录。
- 普通删除可凭持久回执即时或冷重放，核对操作类型和请求哈希；覆盖回执查询与 Item 授权间竞态。无回执不视为成功，审核经验仍使用专用删除入口。
- 引用到管理页的链接绑定工作区、Item、候选和冻结版本。分页外目标精准读取；迟到旧回包不会覆盖已知新版本或把归档目标藏在已保存标签。
- 审核、筛选和其他客户端操作不会丢弃正在编辑的草稿。用户读取最新版本后可继续更正，新版本重置验证。

- 桌面集成覆盖精准导航、旧 capability 回退、双客户端修改、列表筛选后保留草稿，以及迟到旧版本与并发归档。

- 根项目及测试、桌面 main/preload/renderer、移动端类型检查通过。Storage/移动端边界检查、相关 ESLint 与 `git diff --check` 通过。
- `npm run desktop:package` 完成并通过包内资源校验。

真实模型独立运行了以下两条现有 E2E：

1. `tests/e2e/task-experience-review.real-llm.test.ts`：受控首错 20 → 用户纠正后 30 → 后台提案与审核 → 关闭自动学习 → 新附件 18。断言实际附件、范围、HTTP 携带、采用及独立效果；首错与用户审核是验收夹具控制，不宣称全流程无人工参与。
