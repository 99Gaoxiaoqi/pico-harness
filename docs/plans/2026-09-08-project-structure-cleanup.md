# 项目结构调整任务

基线：4b64eabd。用户已授权先拆分任务再实施。每个代码任务独立 worktree，主代理在集成分支验证后串行合并 main。

## 实施清单

- [ ] A｜退役旧记忆执行链：移除旧 Worker/Proposal/Scheduler/Recovery、旧管理服务和 Repository；独立保留新链所需类型与内容校验，迁移有效测试。旧 workspace memory 表和兼容校验不变。
- [ ] B｜整理文档：当前架构、使用指南、决策记录、课程/历史计划分目录；归档根已完成 PLAN，修正记忆迁移/来源抑制的过期描述，更新链接。
- [ ] C｜拆分 Desktop 前端：独立路由页面与纯投影，保持 store、会话身份、重连和界面行为。
- [ ] D｜拆分 Engine：将子代理执行与上下文处理形成完整职责模块，保留共享预算、运行身份与工具安全边界。
- [ ] E｜整理测试和诊断脚本：先建立递归测试发现，再按领域移动集成测试；保留平台/专项测试入口，诊断探针去掉个人硬编码路径。
- [ ] F｜收拢 Desktop Provider 配置服务：在 A/C 集成后串行调整业务状态所有权；保持任务启动与配置修改共用的锁及恢复顺序。
- [ ] 集成｜最终类型检查、构建、架构检查、受影响集成测试及测试发现对账；审查差异后提交、推送并清理任务 worktree。

## 范围与验收

不新增产品功能，不改变协议、模型提示词、记忆规则和 UI 交互。保留三个共享 packages；保留 daemon 升级互斥守卫、文件锁/原子 JSON、SQLite 兼容表和跨平台安全能力。本机缓存与未跟踪的记忆技术文章/配图不纳入提交。

删除旧实现前核实所有调用；属于当前行为的测试迁移后保留，仅验证退役实现的测试随之退役。移动测试后必须核对迁移前后完整测试文件清单，防止 glob 漏跑。最终以实际执行结果记录验证，未执行的检查不标通过。

并行边界：A 拥有记忆及其 Runtime/daemon 接线；C 拥有 renderer；D 拥有 engine；B/E 由主代理在集成分支处理。测试移动在 A/C/D 合并后执行。F 等 A 完成后启动，避免修改同一个中央服务。

涉及并发和恢复的调整均保持原有状态对象与锁的所有权；验证失败停留在集成分支，不更新 main。回退使用普通 revert，不重写共享历史。
