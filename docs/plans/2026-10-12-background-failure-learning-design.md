# Pico 后台失败经验学习方案与评审

> 实施时的最终选择已调整：采用「自然验收后自动晋升」，覆盖固定 Node 测试目标与静态命令的目录、配置、本地依赖准备条件。验收票据在真实复测派发前冻结，后台只校验和保存，不主动重跑命令；自由根因仍隔离。详见 [实施记录](2026-10-12-execution-learning-implementation.md)。下文保留方案评审时的历史取舍，不作为当前自动出口的规格。

推荐采用方案 A 的持久任务与独立后台身份、方案 C 的空闲调度和状态展示，并以方案 B 的事实与推断分层限定自动产出。首版允许后台记录可回查的同命令恢复观察案例；模型生成的根因和行动建议仍隔离为候选。三份独立方案、交叉评审及收敛方案的聚焦复核已完成，本文件为设计交付，尚未实施运行代码。

主任务保留必要的失败诊断与修复，只等待小型持久登记，不等待后台反思模型。历史案例明确标为观察，不能称根因或通用修复规则已验证。

## 共同基线

- `memory_learn` 为同步、独占工具步骤；调用受当前 live Run、Session owner fence、工作区信任、工具授权及记忆设置约束。
- 候选不召回。当前确认条件是同 Session、提案后的同原始 Bash 命令及声明边界，三次不同、完整的原生成功；失败及成功来源保留。
- 当前候选晋升为工作区范围的 `failure` 记忆，带 `execution-evidence`；事务、幂等、删除墓碑和人工编辑撤销验证标识已实现。
- 普通用户记忆的 completed/checkpoint 提取已有后台生命周期、冻结设置版本及删除代次、恢复和回执；session lane 队列只存在进程内。
- 本轮方案覆盖自主触发、后台执行、证据准入、恢复和用户状态；不构建通用任务平台，不改变用户已有代码。

依据：[执行经验工具](../../packages/pico-host/src/execution-lesson-tool.ts)、[存储事务](../../packages/storage/src/sqlite/sqlite-memory-item-store.ts)、[现有后台提取](../../packages/pico-host/src/atomic-memory-runtime.ts)、[调研结论](../research/2026-10-12-coding-agent-failure-learning.md#学习触发时机和主流程延迟)。

## 方案 A 独立持久任务与保守验证

以独立学习 worker 为核心，保留三次验证规则。前台每个准入 Run 在派发工具前登记 open 任务，捕获当前已提交候选的提案代次及设置/删除/编辑代次；completed 或安全 checkpoint 冻结事件范围并转为 ready。没有失败及待验证候选时空结算，主任务不等待反思模型。

新增 `execution_learning_jobs`，包含确定性 jobId、workspaceKey、Session/Run、固定事件区间及摘要、策略代次、状态、retryAt、累计模型额度、lease 和递增 fencing token。worker claim 和提交在短事务中验证 token；候选保存/晋升、任务完成及回执一起提交，成功后推进处理位置。重启恢复 ready 或过期 claim；open 任务只从合法持久终态恢复，证据缺失不猜测。

后台抽出只读原生证据验证器，不调用 `memory_learn.execute`，不伪造 live Run、不接管源 Session owner。保留当前同 Session、同命令三次规则，但后台提案采用提案代次：后续 Run 在工具派发前读到该代次，才有资格验证该提案。旧同步候选继续用当前独占步骤的事件序列边界；修订递增代次并清票。

每用户目录一个活跃 worker，宿主退出后留待下次启动恢复。提炼与一次格式修正共用持久调用预算；重启不重置额度。提交前后检查信任和冻结策略；加入粗粒度工作区 userEditRevision，人工编辑可阻止旧任务提交，但可能取消无关候选。后台 create-if-absent，不自动覆盖用户更正。

主要改造是 schema v10→v11 的专用任务与代次、claim/fenced commit、共享证据服务、Host 启停及 Run 派发/完成接线。验收关注崩溃恢复只提交一次、旧 lease 拒绝、提案前零票、后续三次自然确认及删除/编辑/设置竞态。优势是独立身份和跨进程边界明确；代价是每个准入 Run 增加轻量登记，候选确认慢，同命令三次仍不是因果证明。

## 方案 B 观察事实与主张验收分离

后台先保存一次真实事件的窄观察，把 lifecycle 与 assurance 分开。完整非零退出是执行失败；权限阻断、超时另分类，必须有明确 Host 事实，不能按错误文本猜测；原因和建议属于 hypothesis。明确用户纠正走既有用户证据路径，不变成执行证明。原生字段没有耗时，事件差只能称观察时长。

失败后更换命令成功，可以形成失败→改动→验收关系，前提是能核对目标及改动。早于提案的历史结果只能支持 retrospective 观察；冻结主张、条件和验收谓词之后的实际执行才支持 prospective 验证。单次观察默认留在候选库；正式建议要求支持证据与适用条件，不能因 exit=0 给任意文字根因贴 verified。

引入 Host 注册的少量具名验收谓词，以及 claimHash、predicateId、scopeHash、evidenceIds、验证边界和 verdict。跨 Session 补证需要同工作区、适用配置版本与可回查来源；明确反例使建议待复核并停召回，无关失败不能算反证。旧三次记录保留原语义，不沿用其计数为新候选授予验证标签。

前台登记持久线索；completed/checkpoint 或安全终止冻结 settled 范围，异常退出重扫有冻结准入的原生记录。独立后台身份通过 enqueue/claimLease/readFrozenEvidence/commitLearning，事务核对 lease、候选版本、设置/删除代次及摘要，原子保存经验和回执。worker 不执行命令，模型只输出结构化候选和引用。

状态可显示待整理、已保存观察、有修复证据、具名验收通过、待复核，并保留来源及丢弃入口。现有手动 v1 工具继续有效。主要改造涉及证据/验收契约、任务存储、worker、召回身份与 UI。验收覆盖换命令修复、历史观察、跨 Session 自然补证和反例撤销。优势是证据语义准确；风险是谓词、跨 Session 关联及反例系统扩大首版范围，候选如何正式准入还需明确。

## 方案 C 空闲边界与主会话协调

优先自主触发与用户可见状态，首版保留三次提案后自然成功规则。完整原生 Bash 失败只登记引用；completed 后有可回查修复线索才排整理。failed/cancelled 没有处理方式时只留事实；compaction 封存闭合执行范围，idle 只是执行机会，不是验证证据。

建议空闲 10 秒启动、每工作区一项整理、同 Session 未开始范围合并；已运行快照不变。新输入优先，未开始任务延后，已开始模型发 abort；提交时重查前台占用与任务代次。首版每回合一次、每工作区每小时四次模型整理，输入输出硬预算，暂时 Provider 失败最多重试一次；数字作为待实测默认，确定性验票不调用模型。

新增 learning_jobs，冻结范围、策略、状态、lease 与重试时间，重启恢复过期 lease。后台独立 job 身份只读源事件、写记忆库；提案必须晚于真实创建，不能倒填边界。首版 worker 位于当前源 Session 的 Host owner；短提交阶段与 Run admission 共用 gate，复核 owner fence、读取 high-water 并创建候选，随后的新 Run 才能派发。worker 不在反思模型期间持有 gate；若源 Session 已被另一进程占用，恢复延期而不争夺所有权。独立 daemon 需要持久 admission 协调或派发绑定提案代次。

会话每回合最多一条可折叠学习记录：已排队、整理中、形成待验证经验、已保存；等待空闲不显示旋转进度或百分比。MemoryPage 提供默认折叠的待验证入口、真实 0/3 次数、查看来源及丢弃。`learning.changed` 和查询协议投影持久状态；只有正式事务提交后显示已保存，不能用点击赞同伪造执行票。

涉及 Host 空闲调度、全终态接线、短 admission 协调、证据服务、任务表及两处 UI。验收涵盖前台终态受理后返回、输入抢占、重启恢复、候选不召回和三次自然验证。优势是体验清晰、可渐进交付；代价是后台依赖源 Session owner 的可用性，严格门槛导致待验证积压，跨进程 admission 与 gate 的具体实现需要评审。

## 交叉评审

三个方案作者均完成了对另外两份方案的只读交叉评审。主要共识是采用 A 的持久化骨架和 C 的状态投影；分歧是首版是否继续把三次提案后成功作为唯一自动出口。最终采用 B 的窄观察思路，保留手动 v1 的三次验证，而不给自动案例授予 v1 的确认身份。

| 评审问题                           | 场景                                                           | 收敛决定                                                                                        |
| ---------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 触发和登记之间可丢任务             | 失败已进事件库，任务登记前进程退出                             | 派发前持久记录原准入；两个数据库用可恢复协议连接，不倒补授权                                    |
| 非正常终态不能借用现有用户提取授权 | 用户提取对非 completed 有 policy_denied；open 任务没有正常完成 | 学习使用自己的冻结准入；安全终态结算完整 settled 事实，未结算执行保持未知；取消不自动提炼或晋升 |
| C 的 source owner gate 覆盖不足    | 校验 fence 后 Session.close 释放 owner，另一进程开始派发       | 首版不用 source Session gate 协调后台提交，以独立 job fencing 和只读源证据为权限边界            |
| 严格门槛导致候选长期零确认         | 修复早于后台提案、改了命令或下一次另开 Session                 | 自动出口是历史执行观察，保留手动 v1 的三次门槛；换命令根因建议不直接发布                        |
| 原生成功不能证明文字根因           | 命令三次通过但模型归因仍错误                                   | Host 确定性渲染事实案例，模型根因和行动规则只留候选                                             |
| 保存状态含义混淆                   | 候选落库被显示为已学会                                         | 区分任务受理、候选记录、观察案例提交及手动 v1 正式确认                                          |
| 用户更正和丢弃无法挡住旧任务       | 用户改全局记忆，或另一会话纠正原因，旧 worker 仍提交           | 用户级管理编辑/丢弃代次；新输入屏障；旧推断不换代次原样重试                                     |
| 每次输入 abort 可能浪费费用        | 高频输入导致反思反复启动并取消                                 | 空闲启动、有限累计尝试；已 claim 范围不改，取消也不重置预算                                     |
| 确定性错误摘录仍可能不安全         | 输出含凭据或指令式文本                                         | Host 定位原文、长度限制、完整正文安全校验及低信任转义，不安全时省略原文或跳过案例               |
| 观察元数据丢失会被误分为用户证据   | 现有召回用 sources 非空回落 user-evidence                      | 持久来源类型和可用性判定贯穿存储/协议/召回；元数据失配排除，不回落用户事实                      |

方案 A 和 B 的作者另对下述收敛范围进行了聚焦复核，未发现新的设计阻断；提出的内容安全、来源不可降级、执行配对和幂等身份约束均已纳入。此结论为静态设计评审，不代表已实现或已通过运行验收。

## 推荐方案

### 首版产出与边界

首版提供三类明确不同的结果：

| 结果             | 来源和准入                                                   | 是否召回                                         | 用户文案                             |
| ---------------- | ------------------------------------------------------------ | ------------------------------------------------ | ------------------------------------ |
| 自动执行观察案例 | Host 核实冻结历史中的同命令失败→自然成功，确定性生成事实正文 | 同工作区、具体执行入口匹配时最多一例，低信任参考 | 已记录执行案例，可参考               |
| 自动候选教训     | 后台模型提出根因、适用条件或建议；尚未有对应主张验收         | 不召回                                           | 待验证教训                           |
| 既有手动 v1 经验 | 继续使用 memory_learn 的真实提案后、同 Session 三次自然成功  | 沿用现有策略                                     | 执行成功记录支持的经验，展示实际次数 |

自动案例不使用 confirmed、verified 或 verificationCount 的既有验证语义；不以一次成功替换 v1 的三次要求。它描述历史观察，不断言根因、同目标业务验收或未来成功。旧 v1 的执行成功也不改称根因正确。

首版自动配对收紧为同一个已准入 Run 的闭合历史范围，确保两条执行同 workspace、Session、工作目录、原始命令和声明边界参数。成功的 dispatch 和 result 都必须晚于失败 result；两条 operation 均已 settled，事件不 partial、不属于恢复伪结果或 fork 导入，原生进程事实完整且分别非零/零退出。按原失败选择首个满足条件的自然成功，不能把早已启动、晚返回的并行成功算作恢复。

模型只筛选可复用的来源引用、提出隔离的 hypothesis，不改写可信事实，也不能填写可信 verdict。错误摘录由 Host 从原始结果定位，标明截断/脱敏；正文称失败执行输出摘录。命令、标题及摘录组成的最终正文复用现有安全检查。不安全时不复制原文；无法得到安全且有用的案例则 skipped，不自动记录凭据。

换命令修复、跨 Run/Session 的自动配对、无修复的单次失败和 Provider 故障，不在首版自动发布经验的范围内；原事实保留在执行账本，有值得分析的关系可留候选。明确用户纠正仍走用户证据入口，不混成执行证明。不新增通用验收谓词框架、自动重跑、Rules/Skills 导出或自动反例治理。

### 触发与持久恢复

Host 在准入 Run 的第一次相关派发之前，以小型事务登记 prepared admission，冻结 workspace/Session/Run、用户授权工具面、设置版本、删除及管理编辑代次。登记失败时主任务继续，但该范围没有后台学习资格，不能在恢复时使用当前设置倒补。

checkpoint 与终态各登记独立的不可变窗口，保存原准入身份、范围起点/终点和规范事件锚；worker 只处理 ready 窗口。安全终态只封存已 settled 原生事实，unknown 派发不推断结果。cancelled 结算为 skipped，不额外调用模型或发布案例；failed 没有恢复配对时仅结算事实，不提炼修复规则。

同 Run 的 checkpoint 与 terminal 窗口可以覆盖相同失败前缀，已封存窗口不扩展。checkpoint 的无恢复结算不墓碑化失败身份，后来同 Run 的合法窗口仍可观察到自然成功。以原失败执行身份去重，不用 jobId 去重案例。

跨两个数据库采用可恢复的顺序协议：先登记、后允许派发；登记后没有派发则空结算；终态持久化后未登记窗口，则启动恢复从 prepared admission 和合法原始边界补齐。没有原准入、源 Session 已删除/归档、证据缺失或摘要失配时，明确 skipped/invalidated。既有用户事实提取 cursor 不作为失败学习的完成凭证。

初版运行于现有宿主生命周期：每用户目录一个活跃 worker，空闲时 claim，前台输入优先；宿主退出停止 claim，有限等待后取消并保留可恢复任务。无需独立 daemon。建议空闲十秒、每工作区每小时最多四次提炼；它们是待实测预算默认，不是正确性保证。确定性证据筛选和案例渲染不消耗模型调用。

每个原失败身份累计最多两次模型尝试，重试、取消和跨 job 的再整理共用；调用前持久占用额度，崩溃不能恢复额度。输入/输出需符合现有窗口预算，单请求使用有限 deadline；费用未知仍显示未知。没有可复用配对或无需假设时可零模型结算。

### 后台写入与用户优先

抽出共享只读原生证据验证器，前台工具继续使用 live Run/Session owner，后台通过独立 jobId、leaseEpoch、原准入和冻结范围获得受限写入资格。worker 不调用 memory_learn.execute，不伪造 Run 或 toolCall，不争夺源 Session owner。

提交短事务检查 job fencing token、冻结设置/删除/编辑代次、候选版本及模型额度；原子写案例或候选、来源绑定、幂等回执和任务结算。正式保存成功后才更新处理位置；模型完成或队列受理不能代表保存完成。源证据读取发生在事务外，调用方只能使用 Host 校验的固定引用，模型不能指定数据库作用域或请求权限。

案例幂等身份绑定 workspace/Session、原失败 eventId、命令/边界摘要与规则版本，不绑定 jobId 或模型文字。相同失败在重复窗口、重启和提交后重放中返回同一结果。用户删除或丢弃留下该失败身份的墓碑，旧范围不能通过换成功来源或 claimHash 重建。

管理编辑/丢弃代次采用用户级，或按实际 item scope 更新，不能只按 UI 所处 workspace 更新；否则全局更正挡不住另一个工作区旧任务。相关代次与用户写入同事务提交。设置关闭后再开启不会重新授权旧范围；删除同时清理关联候选和回执中的正文，保留最小墓碑和无正文观测。

新用户输入立即暂停该工作区旧模型摘要的提交；正在执行的调用可取消，但仍计尝试。未处理的新用户上下文不能被旧推断忽略。后续整理创建包含最新用户上下文的新冻结任务，旧推断标过时，不能只刷新代次原样重试；失败身份的累计预算和墓碑仍生效。明确纠正被用户证据链接受时也更新学习编辑代次。

### 来源与用户界面

观察案例使用新的 `execution-observation` 来源类型及独立 Host metadata，标明 retrospective、配对来源和内容摘要，不能借用 `executionEvidence.verificationCount>=3`。

来源类型须持久保存，不能只依赖可选 metadata：metadata 缺失、绑定错误或内容 hash 不符时，案例不参与召回并显示来源不可用，不能进入当前 sources 非空→user-evidence 的回落路径。人工更正明确转为 manual，并撤销原生观察标识；归档/恢复只影响召回资格，不伪造新验证。

Host 用原始命令/声明边界摘要及具体执行入口约束召回。只有当前请求或主动搜索明确提供相应命令/入口、且 Host 能匹配范围时才注入；缺少事实时跳过，不能凭模型 taskFamily 或“测试”等泛关键词放宽。最多一例，沿用当前整体条数/token 预算及低信任包装；本阶段不承诺任意自然语言任务都会自动命中。

会话每回合最多一条可折叠学习状态，等待空闲不显示旋转百分比。区分持久任务受理、整理中、候选已记录、案例已记录、旧 v1 正式经验提交、未形成案例或暂不可用。记忆页提供观察/候选的默认折叠入口、来源及丢弃操作；只有 v1 实际取得票才显示三次计数。

新增状态查询与 `memory.learning.changed` 通知；通知只提示刷新，界面以持久查询及单调资源版本为准。沿用 memory.changed 刷新正式条目，迟到通知不能恢复已删条目，也不将工具 accepted 当作成功提示。

### 实施边界

| 层次      | 拟改造                                                                                                          |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| core      | 专用 job/原准入/观察案例契约，来源类型与可用性；模型不能填可信字段                                              |
| storage   | v10→v11 增量迁移：专用任务、轻量控制代次、持久来源标识；claim/fenced commit、墓碑和回执；保留 v9→当前的增量兼容 |
| pico-host | 前台准入登记、闭合窗口封存及恢复、共享证据 reader、独立 worker、模型费用归因与宿主启停                          |
| runtime   | 复用 lifecycle/优先调度思路、观察召回范围和预算；不扩大用户事实提取输入                                         |
| protocol  | 观察 metadata、学习状态查询/通知、来源不可用语义及严格校验                                                      |
| desktop   | 会话折叠状态、记忆页观察/候选管理；保留用户已有 UI 修改                                                         |

本轮自动观察不需要 proposalEpoch 前瞻绑定或 C 的 source owner gate；不能同时实现两套不必要的协调机制。将来若自动晋升自由文本的前瞻主张，再独立设计派发与提案代次的绑定。

### 验收与回退

1. 一条集成主路径：原生失败→修复→同命令自然成功→持久终态；后台模型被可控延迟时前台仍完成；最终原子保存一个观察案例，候选不混入用户事实。
2. 持久失败路径：登记后未派发、终态后未封存、checkpoint 与 terminal 重叠、claim 后崩溃及提交后重放；重启只产生一个案例，旧 lease 被拒绝，预算不重置。
3. 准入反例：并行成功早于失败派发、命令/工作区/边界不匹配、partial/recovery/未知结果、设置变化、删除/编辑/丢弃以及新用户纠正，均不能造成旧推断或伪证据提交。
4. 来源与界面：危险输出不持久传播；metadata 失配不回落用户证据；迟到状态不能复活删除记录；accepted、候选与保存的文案对应真实持久状态。
5. 真实模型验收：从观察案例挑选一条有明确错误信息的任务，在新 Session 显式匹配命令入口后，利用参考完成首次实际检查；检验主流程没有为长期学习增加同步模型轮次。保留当前 memory_learn v1 回归。

验收证明调度、事实与复用路径，不证明长期收益或根因正确率。实现后关闭自动学习可停止新任务；旧手动工具继续可用，已记录案例可归档或删除。数据库回退需恢复升级前备份，不能直接降低 schema 版本。
