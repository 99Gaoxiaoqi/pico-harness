## 阶段一：修复可靠性

### A1. 恢复时刷新页面，保留作用域和发送锁

- 在移动 Store 增加内部 `syncRevision`：每次当前连接成功同步后递增。`generation` 继续负责电脑/工作区切换与迟到响应围栏，不用它模拟普通重连。
- SessionSettings、SessionActions、各设置列表及工作栏/文件/终端列表读取按 `connected` 与 `syncRevision` 恢复；断线时停止新的读取/写入，恢复后读取最新快照。保持非秘密表单未提交内容，不能用重挂载整页清掉草稿或编辑输入；保留密钥原有清空规则和 revision 冲突检查。终端只刷新/重新挂接显示，不重建进程或自动恢复未确认输入。
- Store 消费 `subscribe()` 返回的首批 replay，保留后续分页/实时事件已有交付方式，不把首批事件同时加入两条路径。同步期间先暂存刷新信号，恢复可请求状态后再通知消费者，避免回放回调在 syncing 阶段发出被拒绝的读取；恢复时以新快照为准，不让历史通知把更晚快照倒退。
- 保留 transcript 的历史补齐、视口锚点、原业务幂等键及按会话作用域共享的发送锁；不新增公开 RPC。

涉及 `store.tsx`、`useSessionTranscript.ts`、`SessionSettings.tsx`、`SessionActions.tsx`、设置列表、`Workbar.tsx`、`Files.tsx`、`Terminal.tsx` 的直接消费者。

验收：一条集成场景覆盖打开设置→断线→电脑结束任务并修改设置→自动恢复，页面自动刷新且草稿仍在；关键失败路径覆盖恢复过程切换电脑，旧回放/读取不得写入新电脑。

### A2. 将配对确认做成可恢复的最后一步

- 单一活动配对拥有独立取消围栏。提交领取后，把 claim、期限、可信 origin/gatewayId 以及随后领取的 deviceToken 保存到 SecureStore 待确认记录；AsyncStorage 和日志不保存配对秘密。
- 顺序为：保存待确认信息→领取并安全保存设备凭据→发送既有 ack→确认完成→落正式 token/电脑列表→最后清待确认记录。完成前显示“等待确认”，不显示可连接的成功条目。
- TTL 内仅重试原 ack；重启手机或恢复前台继续同一待确认记录。取消后迟到响应不能保存凭据或自动连接。
- ack 回执丢失、claim 已失效或网关重启时，用已领取的设备凭据认证并核对 gatewayId/origin。现有网关只允许 `pairedAt` 已确认设备认证，可据此核对已完成结果；瞬态网络错误继续待确认，明确撤销/未完成过期则清理临时状态并引导重新配对。
- 小范围修正网关 ack 的提交时序：未落盘的 `pairedAt` 不能被认证逻辑观察成成功；提交失败恢复旧状态；并发重复 ack 等待同一提交，已完成重复 ack 不改写原确认时间。
- 保留原期限、电脑批准和网关重启撤销未确认授予的安全策略。复用现有 ack/认证入口，不新增 RPC、持久化 Schema 或延长秘密有效期。

涉及 `store.tsx`、新增窄范围配对存储、`remote-client` 配对入口及 `remote-gateway/pairing.ts`、必要的认证提交检查。

验收：HTTPS 配对集成覆盖批准后丢 ack 响应→重启手机→恢复为同一个有效设备；关键失败路径覆盖未确认授予过期/网关重启与 ack 落盘失败，均不能产生假成功、重新批准或长期有效临时凭据。

### A3. 允许同协议版本增加未知方法

- capabilities 仍严格校验版本、gateway 身份、数据类型和帧预算；方法列表须为合法字符串列表，未知方法只被忽略，手机仅暴露本地白名单与电脑能力的交集。
- 缺少已知方法/必要安全能力时禁用相应功能并解释原因；保留终端 owner 隔离、审阅幂等及权限守卫，不把未知字段当作权限。
- 破坏性版本变化继续拒绝连接并给更新指引。记录手机/网关/Host 的实际支持组合。

涉及 `packages/remote-client/src/index.ts`、能力展示与相关集成；预计不修改公开协议 Schema。

验收：当前手机遇到同版本增加的未知方法仍可读会话；旧电脑缺少新功能只禁用相应入口。关键失败路径确认身份不符、协议版本不兼容、缺必要隔离能力仍拒绝。

### A4. 区分普通拒绝与已发送命令的未知结果

- 本地校验、证书/DNS等已证明未执行的失败保留原错误；有效匹配的服务端业务拒绝也不转成 unknown。
- 请求发出后，响应非 JSON、requestId 不匹配、成功 payload 无法校验或响应超过预算，命令标记“结果未确认”。用客户端私有错误来源判断，不按错误文案猜测。
- 检查所有受影响写入口：发送、审阅沿用原持久幂等键；无可靠幂等回执的操作先核对电脑状态。不能重新生成键或自动重发；终端输入仍暂停等待用户核对。

涉及 `remote-client/index.ts` 与受影响 UI 回调。保持服务端已完成操作和未知结果冻结行为。

验收：集成模拟命令已执行但返回不匹配响应，手机进入待核对且不发生第二次写入；关键失败路径确认有效业务拒绝/本地超预算仍可正确显示普通失败。

### A5. 先对齐失败的审阅集成断言

上轮 `client-transport.test.ts` + `mobile-session.test.ts` 为 14/16，两个失败涉及新增幂等键与“手动刷新不解除 unknown”的契约。实施开始先复现，再对齐断言与独立存储夹具；禁止删掉未知结果保护来让旧断言通过。

每个集成场景使用独立 recovery storage，失败也清理自身订阅/请求，避免一个失败遗留 pending 污染下一场景。验收继续证明刷新不解冻、原键重试取得持久回执、重复提交不产生第二个续跑。

## 阶段二：补齐产品与数据边界

### B1. 按电脑清理本机数据

- 提供“清除这台电脑的本机数据”与“解除配对并清除本机数据”。分别说明保留凭据与删除凭据的区别；两者均不删除电脑会话、取消任务或停止终端。
- 清理完整覆盖对应电脑的草稿文字/图片、冻结发送、审阅待确认记录、配对记录、成果缓存和内存状态，不调用 `AsyncStorage.clear()`。
- 先阻止该电脑新写入、作废控制器/存储围栏、停止配对与下载，再串行排空持久化写队列并删除；删除失败不得显示全部完成，重复执行可继续清理，迟到回调不得复活记录。
- 有未知结果时先提供查看状态/原键恢复；用户仍明确清除时，说明将放弃本机恢复记录、电脑操作仍可能已执行。删除后不得把原操作包装成新的自动重试。
- 新成果缓存使用电脑哈希子目录，并把下载取消/清理范围按电脑隔离。旧平铺哈希缓存不能反推归属，保留显式“清空全部旧版成果缓存”，说明影响其它电脑旧缓存；按电脑清理不得假称旧缓存也已全部删除。

涉及草稿仓库、审阅存储/控制器、`artifact-cache.ts`、配对存储；Store 与 Settings 由集成所有者接入。

验收：双电脑集成中清 A 后 A 数据不复活、不重发，B 数据保留；未知结果只有明确放弃才能清除，旧缓存仅由显式全量操作删除。数据删除不可回退，产品必须提供明确确认。

### B2. 隐私、支持和客观数据说明

- 未配对或断网时也可进入“隐私与支持”；内置说明覆盖手机凭据、草稿/图片、审阅恢复记录、成果缓存、直连电脑及电脑调用用户配置模型服务的数据流向与删除方式。
- 政策 URL、支持 URL/邮箱和发布主体集中配置，不使用假网址或虚构主体。正式包不得有占位发布资料；按最终真实行为填写商店隐私/Data safety 声明。
- 展示版本和构建号。安全诊断只包含连接阶段、错误码、版本等必要信息，不含凭据、配对 JSON、正文、完整路径和秘密配置。

依据：Apple 5.1.1(i) 要求 App 内易访问的政策链接，Google Play 允许 App 内链接或政策文本；正式渠道资料须配套。2026-10-04 核实 [Apple](https://developer.apple.com/app-store/review/guidelines/#privacy)、[Google Play](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)。

验收：离线未配对仍可阅读内置说明；候选包政策/支持入口真实可用且与 B1 实际保留/删除行为一致。

### B3. 配对准备与可执行的错误指引

- 首次入口给出电脑启动、可信 HTTPS/公网准备、生成二维码、电脑批准四步；现有用户也能从帮助进入。
- 按证书、DNS/不可达、配对过期、授权撤销、权限不足、协议不兼容、未知结果给相应动作；仅网络瞬态问题提供重连，撤销/过期指向重新配对，权限问题指向电脑授权。
- 扫码权限拒绝后提供系统设置入口与粘贴替代；不忽略证书错误、不自动开放防火墙或扩大授权。手机检查仅报告实际能测的连接结果，不把电脑 doctor 当外网验收。

验收：未配对用户可找到完整准备步骤；相机永久拒绝时仍可粘贴配对；证书错误、设备撤销和未知结果各有正确动作且不触发盲目重试。

### B4. 去掉多余麦克风权限

在 `app.json` 为 `expo-camera` 配置 `recordAudioAndroid: false`、`microphonePermission: false`，为 `expo-image-picker` 配置 `microphonePermission: false`，阻止 Android 依赖重新加入 `RECORD_AUDIO`。

验收必须重建两端原生项目，不复用旧 native payload 只换 Hermes：实际合并 Manifest 无 `RECORD_AUDIO`，实际 iOS Info.plist 无 `NSMicrophoneUsageDescription`，扫码/拍照/图库仍正常。

## 阶段三：候选包与真机验收

### C1. 固定版本与签名产物

- 复用现有 Expo prebuild、Gradle、Xcode 构建路径；不强制引入 EAS。固定源码提交和明确纳入的输入框修改，记录版本、构建号、源 SHA、产物 SHA-256 和签名指纹。
- 设置并核对 `ios.buildNumber`、`android.versionCode` 高于目标渠道现有编号。Android 制作发行签名 APK；选择 Google Play 时同时制作该渠道所需 AAB。iOS 生成面向设备的 Archive/IPA 或 TestFlight 候选，而非 Simulator ZIP。
- 原生配置已变更，两端都重新原生构建。签名秘密只在本机/受控构建环境配置，不提交到仓库或发送到聊天。
- 手机、网关、Host 归档为同批候选，并单独验证支持的旧/新组合。校验已有内测到正式签名的安装升级路径；不兼容时提供真实的重装/重新配对说明，不宣称无缝升级。
- 增加窄范围移动发布验证入口，防止发布包缺 JS、资源或使用错误签名；不改变现有必需 CI/Git checks，不绕过 hooks。

| 场景                 | 明确通过标准                                                                     |

| 安装/升级/离线冷启动 | 真机可安装，离开 Metro 可启动；升级后的凭据、草稿和待确认记录按声明恢复          |
| 蜂窝配对与错误恢复   | 关闭 Wi-Fi 可完成配对；过期、撤销、证书错误均无假成功或校验绕过                  |
| 模型与审批/审阅      | 真实模型发送、流式完成、审批写入、意见续跑和成果查看闭环成功                     |

| 基本读屏与系统权限   | 关键按钮、禁用原因、当前状态可理解；拒绝相机/图库后可继续使用替代路径            |

| 版本组合             | 旧手机/新电脑保留已支持主路径；新手机/旧电脑缺能力时清晰禁用；安全能力缺失仍拒绝 |

涉及模型行为仅使用既有 `tests/e2e/remote-direct.real-llm.test.ts` 真实模型主路径，确认 `RUN_LLM_E2E=1` 且非 skipped；不扩充无关模型评测。

### C3. 公开商店发布的附加条件

需要真实发布主体、隐私/支持地址、Apple Team/签名环境、Android 签名环境及目标渠道已有最高构建号。完成代码阶段无需等待这些资料；定稿政策和正式构建前再取得对应信息。

审核人员须能按说明进入隔离演示电脑和可用配对流程；不提供已过期二维码，不暴露真实工作区或凭据。审核环境仅含测试数据与最小授权。保持服务在审核期间可达，准备首次配置与核心功能的审核说明。[Apple 送审要求](https://developer.apple.com/app-store/review/guidelines/#before-you-submit)。

满足代码/真机门槛后，可形成可审查的发布候选；上传商店或公开发布按后续用户指令执行，不将“制定方案”视为已授权发布。

## 并行所有权、验证与回退

实施前由主代理固定 `syncRevision`、待确认配对、按电脑清理与结构化错误的最小内部契约，然后按清晰边界拆分。只读规划不创建 worktree；并行开发使用独立任务分支/worktree。

| 所有者   | 独占文件范围                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 主代理   | Store/core、配对存储、网关 ack/认证、协议/锁文件、App/Computers/Settings/app.json 接入、最终集成与原生打包 |
| 子任务一 | remote-client、transport 集成：能力兼容、响应来源与 unknown、旧审阅断言及夹具隔离                          |
| 子任务二 | draft/review 存储与控制器、artifact-cache、新本地清理模块及独立集成：按电脑删除与防复活                    |
