# Pico 经验学习闭环缺陷修复方案

2026-10-13。当前阶段：方案已制定，尚未实施代码修复。

目标是修复已经复现的闭环缺陷，完成新桌面包验收及安装交付。保留现有 v12 数据库、新旧协议隔离、权限检查、用户确认与执行验证分离，以及前台任务优先的后台机制。

依据：`pico-learning-adversarial-review/findings.json`、`pico-packaged-computer-use/verification.json`、当前调用链与集成测试。前次实际桌面包已通过审核、更正、停用、重启持久化主路径；这些通过项作为回归基线。真实模型记录的展示验证不等同于本轮重新执行真实模型测试。

## 待修复清单

| 优先级 | 缺陷 | 用户影响与修复方向 |
| --- | --- | --- |
| P1 | 普通删除残留经验正文与引用 | `memory.delete/deleteItem` 删除 Item 后，候选及派生内容仍存在。新来源的删除统一走经验审核接口；清理派生正文并保留无正文操作回执。 |
| P1 | 三个记忆标签文字和数量不可见 | 用户难以找到审核入口。数量样式限定到专属节点，避免覆盖 Astryx 内部背景与标签。 |
| P2 | 版本冲突导致草稿丢失 | 另一客户端确认后，候选移出筛选、编辑器卸载。选中详情独立于列表筛选保持挂载，保留草稿并显示最新状态。 |
| P2 | 归档后更正显示启用，实际不可引用 | 发布新版本时，候选与 Item 必须原子进入 active；验证重置 unknown。 |
| P2 | 迟到详情使管理版本倒退 | 所有管理候选回包按 recordRevision 单调合并；冻结的实际引用独立保留。 |
| P2 | v2 隐藏原生 Node 候选管理 | 同时读取并呈现原生执行候选与通用经验，沿用各自已有接口及权限检查。 |
| P2 | 任务摘要及原生入口丢失工作区 | 审核/管理链接携带 workspace、tab；项目选择和新增路径保留已有查询参数及相关锚点。 |
| P2 | 召回预览的限制没有说明 | 保留工具权限门禁，解释管理页预览不能证明具体任务中的工具经验引用；空结果不暗示保存无效。 |
| P2 | 页头“新任务”文字与背景同色 | layers.css 必须先于所有其他 CSS 加载。已由同一 HTML/CSS 的导入顺序对照确认根因。 |
| P2 | 未形成提案的观察被计作经验 | 空内容、unneeded、invalidated 等记录显示观察/整理状态；建议、已保存经验与实际引用分别计数。 |

另有一项必须收紧的验证边界：现有 Excel 校验能证明**工具实际选择范围**内的有限数值求和，却不能证明该范围等于用户要求的范围。已复现用户目标 B2:B4、实际工具 B2:B3=10 仍返回 pass 的场景。它不是算术错误，但不能据此向用户表示任务覆盖或建议全文已经验证。

新包尚未替换当前安装版属于交付缺口，纳入最后安装验收。历史展示副本保留旧路径产生的通知 envelope 警告不计为产品缺陷，不通过修改真实历史事件来掩盖。

## 实现决定

### 删除与可信状态

1. Host 的普通删除入口及存储 `deleteItem` 都拒绝 `reviewed-reference`，给出“请在经验管理中删除”的明确提示，与已有普通更新/归档隔离一致。普通内容和原生已验证经验仍沿用已有删除流程。
2. `memory.learning.review(action=delete)` 继续作为新经验的删除入口。复用当前事务中的 `clearExperience`，清理候选正文、派生来源/观察摘要、引用片段及未被其他活候选共享的证据，撤销队列与租约，保留 Host Run 身份审计。
3. 历史 action 保留 operationId、scope、requestHash、时间及必要版本/结果元数据；清除复制的正文、目标文本和适用条件正文。旧操作重放先核验请求身份；候选已删除时返回当前无正文墓碑，不重新执行旧确认。不同请求复用同一 ID 仍冲突。
4. 存量检查只修复有明确删除证据的孤立经验，使用同一清理入口并记录数量。仅缺关联、无法证明删除意图的记录保持不可引用并报告异常，不自动擦除。正式执行前备份相关数据库。
5. `publishExperience` 显式设置候选 lifecycleState=active，与新 Item 的 active 同步提交。用户主动“更正并启用”恢复归档记录；其他客户端的归档变更不在冲突恢复中自动恢复。

不能只把 `invalidateItem` 移到 Item DELETE 后：FK 级联会先删除候选关联，随后无法定位需要清理的经验。

### 详情、草稿与并发

1. 当前详情由工作区/会话 scope 和 candidateId 定位，保存选中快照；列表按标签筛选。列表为空或候选移到其他标签仍保留编辑器、草稿和最新状态说明。
2. 草稿与提交基线分开保存。更高版本只更新当前管理状态；保存冲突后要求用户明确基于最新状态继续。读取失败可重试，迟到旧详情不能解除冲突。
3. 已拒绝、已删除或 NOT_FOUND 的候选保留本地草稿供复制，禁止再保存或启用；查询缺项不能直接当作删除，因为查询有条数上限。
4. 统一按 recordRevision 合并 props、详情、反馈及保存回包；工作区/会话切换使用世代号阻止 A→B→A 的旧请求重新生效。切标签和临时断连不以重新挂载方式丢稿。
5. 同步 inFlight 防止双击。相同不确定失败重试沿用 operationId；修改草稿、动作或确认基线后生成新 ID。
6. 历史引用的内容、contentVersion、referenceHash 和任务身份继续来自冻结 receipt；当前管理版本不能改写本次实际引用。

### 入口与界面一致性

1. `main.tsx` 最先加载 layers.css。在实际 Vite 产物上检查主按钮文字与背景颜色，不额外叠加强制颜色补丁。
2. Memory Tab 的计数使用专属 `memory-tab__count` 类，移除 `.memory-tablist button span` 的泛化样式；保留 Astryx 的标签、选中态和键盘行为。
3. TaskExperiencePanel 接收明确 workspacePath；通用审核链接、原生已保存入口、WorkspacePicker 选择/新增路径均保留路由上下文。MemoryPage 响应 URL tab 变化及 capability 就绪，不能只读首次状态。
4. 当前任务有待审核项时显示“审核任务经验”；已有建议/引用时显示“管理工作区记忆”；只有未形成建议的观察时不显示审核 CTA。设置页管理入口统一称“管理工作区记忆”。
5. 摘要分别表示待审核建议、已保存经验和实际引用。空正文失效记录显示“整理已停止，未形成经验建议”，不显示已沉淀经验数和无意义的内容版本/启用状态。
6. 原生和 v2 查询同时启用。现有 SQL 分别读取 `kind IS NULL` 与 `kind='task-lesson'`，无需新建合并接口或进行前端去重。
7. 管理召回预览明确说明：需要按具体任务的工具权限、附件和适用条件判断的经验可能省略。保持 `toolAllowed: () => false` 等现有保护，不为预览放开执行权限。

### Excel 验证边界

1. Host 从当前任务/目标版本的 canonical 用户输入及当前附件绑定取得明确的工作表与范围；纠正改变目标时更新绑定。首版只处理可唯一确定的单工作表、单明确范围、有限纯数值求和，歧义或不完整证据保持 unknown。
2. 比较用户目标范围、实际工具参数、原生结果声明和独立读取的附件数据。范围未覆盖用户目标时不记录整体 pass，也不直接将任务参数错误归因于经验失效。
3. 能证明使用了无表头求和要点时记录对应采用证据；建议文字中的其他步骤不自动宣称已采用或有效。UI 说明 Excel 验证覆盖范围、表头处理、数据覆盖和求和值。
4. 最终回答文字错误、不同步骤失败、目标不明或范围不匹配都不能自动停用经验。仅当前经验版本、适用条件和实际采用证据匹配，且原生执行结果出现可信矛盾时走现有停用规则。
5. 原有历史 pass 只作为当时工具证据的记录展示，不自动升格为新增目标覆盖检查通过；后续任务按收紧后的条件生成新验证结果。原生 Node 冻结验收保持其原有语义。

## 开发顺序与文件所有权

先由主代理串行冻结删除/回执、归档发布、草稿冲突和验证结论的语义，再并行实现。优先保持现有公开协议、Desktop schema 及数据库 v12；确需内部任务目标字段时由主代理单独处理，禁止三个分支各自修改公共契约。

| 负责人 | 独占内容 | 验收重点 |
| --- | --- | --- |
| A：存储 | 两个 SQLite store、task-experience-storage 集成场景 | 删除、回执脱敏/重放、存量检查、归档后新版本及召回一致性 |
| B：桌面 | TaskExperiencePanel、hooks、MemoryPage、ConversationPage、ExecutionLearningPanel、WorkspacePicker、main/styles 及桌面集成测试 | 草稿、乱序、入口、计数、原生管理、完整样式和预览提示 |
| C：Host 验证 | task-experience-runtime/validation、相关验证与 Runtime 集成测试 | 当前目标范围绑定、采用/验证边界与错误归因 |
| 主代理 | DesktopAtomicMemoryService 删除提示、公共契约协调、集成、真实模型验收、打包和安装交付 | 旧接口兼容、工作区隔离、最终产物及实际运行版本 |

桌面方案与并发方案共享 TaskExperiencePanel，因此归 B 同一所有者。存储的删除和归档修复共享 execution-learning-store，归 A 同一所有者。测试夹具、生成物和锁文件同样保持单一所有者；本轮不引入依赖。

当前工作区包含大量既有未提交修改。执行前保存文件摘要和归属快照，独立工作树以该快照进行验证；集成后只回填本轮修复差异。不得自动 stash/reset，或将用户既有内容混入本轮提交。Git 提交与推送仅在本轮差异可安全隔离时处理。

## 验收门槛

先扩展现有集成测试，不新增内部实现级单元测试。每个缺陷保留一条能失败的回归场景，相关场景可在现有文件内合并。

- 删除：普通 RPC/直接存储拒绝新来源且零写入；专用删除清理派生内容、保护共享证据；重启后重放旧 ID 返回无正文状态，改变请求仍冲突；事务失败整体回滚，迟到 worker 不复活。
- 生命周期：accept→archive→edit_accept 后新 candidate 与 Item 均 active、v2、unknown，实际召回选中新版本；旧反馈和旧 CAS 无法覆盖它。
- 并发 UI：另一客户端 accept/reject/archive/delete 后草稿保留，明确展示最新状态及可操作边界；延迟 v2 详情不能覆盖 v3；冻结 v1 不变；双击只发送一次动作；A→B→A 旧请求被丢弃。
- 兼容与入口：旧接口分页/来源保持原约束；v2 下原生 waiting/invalidated 能查看和丢弃；自动学习关闭仍能管理历史经验；审核跳转与项目选择保留 workspace/tab；失效观察不计为经验。
- Excel：用户目标 B2:B4、工具仅 B2:B3 返回10不能整体 pass；完整 B2:B4=18 可通过；最终回答99不污染正确工具证据；公式/合并/过滤/多范围及歧义目标保持 unknown，不能误停用。
- 构建：相关类型检查和桌面构建通过；CSS 检查实际样式与文字可见性，不能只断言 DOM 存在或 textContent 正确。
- 模型：验证边界修改完成后，在 `tests/e2e/task-experience-review.real-llm.test.ts` 运行一条新的真实模型跨会话闭环，确认20→纠正30→新附件18，并检查实际新附件/参数/原生验证记录。历史截图不替代该执行。
- 桌面包：完整重新 package，Computer Use 在新 `.app` 与隔离真实后端走任务摘要→审核→确认→引用→更正→停用；包含跨客户端冲突、工作区跳转、标签可读、原生管理及完整重启。记录截图、路由、RPC 状态与包指纹。

全部验收通过后，备份当前 App 及相关数据，检查并保存当前草稿/待发送内容，串行退出旧 App 与其对应 Runtime，替换安装包并启动。用窗口 URL、进程路径、v2 capability 和实际管理页确认用户正在运行新包。不能只生成 out 目录产物就宣称安装交付完成。

回退保持 v12：关闭自动学习入口并继续管理历史经验，或回退到支持 v12 的前一代码构建。数据删除完成后不得通过代码回退恢复已删除内容；不得将旧 v11 程序直接接入升级后的数据库，也不降级数据库版本。

完成以上验收即停止。向量库、跨项目推广、Skill 发布、团队同步及通用验证器框架均不在本轮范围内。
